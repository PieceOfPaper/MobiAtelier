# 시스템 메뉴·종료·ESC 기획

> 정리일: 2026-11-03
> 사용자 결정: 우측 상단 시스템 메뉴에 내보내기·가져오기·초기화·옵션·종료를 묶는다. 기본 ESC는 이 메뉴를 열고 닫는다.
> 이전 ESC 종료 확인 팝업은 이 메뉴로 대체한다. 기획 확정이며 새 UI의 구현 완료가 아니다.

## 1. 진입과 표시

**확정**
- 앱 화면 우측 상단에 메뉴 아이콘을 둔다. 툴팁은 `시스템 메뉴 (ESC)`다.
- 다른 UI가 입력을 소유하지 않는 상태에서 ESC를 누르면 메뉴를 연다. 메뉴가 열린 상태에서 ESC를 누르면 메뉴만 닫는다.
- 메뉴는 꾸미기 패널의 열림 여부와 무관하게 사용할 수 있다.
- 메뉴를 여닫아도 캐릭터·배경·카메라·꾸미기 패널 열림 상태를 바꾸지 않는다.
- 메뉴는 종료 확인 팝업을 대체한다. 메뉴의 종료를 누른 뒤 같은 내용의 종료 확인 팝업을 한 번 더 띄우지 않는다.

**구현 세부 제안**
- 메뉴 뒤를 딤 처리하고, 메뉴·하위 화면이 열린 동안 뒤 UI와 카메라 입력을 막는다.
- X·메뉴 바깥 클릭은 메뉴 닫기로 처리한다. 닫는 클릭이 뒤의 카메라 조작으로 이어지지 않게 한다.
- 메뉴를 열던 ESC·클릭이 메뉴의 항목 실행까지 이어지지 않게 한다. 최초 선택을 종료에 두지 않는다.
- 열린 컬러피커는 현재 Dye.md의 다른 작업 시작 정책에 맞춰 미리보던 색을 적용하고 닫은 뒤 메뉴를 여는 것을 제안한다. 그 색 확정은 별도 꾸미기 편집이다. 패널 접기·UI 숨김은 적용·취소하지 않고 피커를 보존한다.

## 2. 메뉴 항목

| 순서 | 항목 | 실행 후 흐름 |
|---|---|---|
| 1 | 내보내기(Export) | 현재 작업의 JSON 내보내기 대화상자 → 성공/취소/실패 → 기존 작업 |
| 2 | 가져오기(Import) | JSON 선택 → 검사·필요한 부분 복원 확인 → 성공 시 작업 교체·이력 삭제, 실패/취소 시 기존 작업 |
| 3 | 초기화 | 코디 초기화 확인 → 성공 시 현재 성별 기본 코디·기본 카메라와 이력 초기화 |
| 4 | 옵션 | 옵션 화면 → 경로 편집·적용 후 다시 시작 또는 돌아가기 |
| 5 | 종료 | 대기 중 자동 저장 처리 → 성공 시 앱 종료, 실패 시 저장 실패 안내 |

- 시스템 메뉴 안에서는 항목 이름도 함께 표시한다. 아이콘만 보고 파일 작업·초기화를 구분하게 하지 않는다.
- 초기화·종료는 다른 항목과 간격을 두어 구분한다. 초기화 확인은 유지한다.
- 실행 취소·다시 실행은 시스템 메뉴에 넣지 않고 꾸미기 창 최상단 아이콘에 둔다.
- 촬영 버튼·이미지 비율·이미지 내보내기는 이번 메뉴에 추가하지 않는다.
- 내보내기 대화상자 취소·실패만으로 편집 상태·최근 내보내기 폴더를 바꾸지 않는다. 내보내기 자체는 이력을 지우지 않는다.

## 3. 종료

**확정**
- 시스템 메뉴의 종료가 정상 종료 진입점이다. 자동 저장 성공을 확인한 다음 종료한다.
- 저장 실패 시 종료하지 않고 재시도·수동 JSON 내보내기·저장 없이 종료의 선택을 제공한다. 사용자 작업은 메모리에 유지한다.
- 저장 없이 종료는 실패 안내에서 사용자가 명시적으로 선택한 경우에만 실행한다.
- 메뉴를 닫는 동작은 종료 취소다. 작업·카메라·패널 상태는 유지한다.

**제안**
- Windows 창 닫기·Alt+F4 요청도 우선 시스템 메뉴를 열어 같은 종료 항목으로 연결한다. 추가 종료 확인 팝업은 만들지 않는다. (2026-11-03 공개 빌드에 구현. 에디터의 플레이 종료는 막지 않는다. 작업 화면 진입 전 경로 지정·복구 안내에서는 그대로 종료한다)
- 강제 프로세스 종료·전원 차단은 이 흐름으로 제어할 수 있다고 보장하지 않는다.

## 4. ESC 입력 소유권

- ESC 한 번은 가장 위에서 입력을 받는 UI 한 곳에서만 소비한다.
- Windows 파일·폴더 대화상자가 열렸으면 그 대화상자가 먼저 처리한다.
- 옵션·초기화·부분 복원·오류 화면이 열렸으면 해당 화면의 닫기·취소·복구 정책이 먼저다. 필수 시작 경로·복구 화면을 ESC로 우회하지 않는다.
- 해당 화면 안에 열린 드롭다운·피커가 있으면 자식 UI가 부모 화면보다 먼저 처리한다.
- 옵션의 돌아가기·ESC는 시스템 메뉴로 복귀한다. 옵션에 입력만 한 경로는 적용하지 않는다.
- 활성 시스템 메뉴에서 ESC는 메뉴만 닫는다.
- 일반 편집 중 열린 드롭다운 → 컬러피커 → 자세한 조작 안내 순서로 먼저 닫고, 그 밖의 UI가 없을 때 시스템 메뉴를 연다.
- 패널이 열렸다는 이유만으로 기본 ESC가 패널을 접게 하지 않는다. 패널은 가장자리 탭으로 접는다.
- UI 숨김 중 ESC는 임시로 시스템 메뉴를 연다. 닫으면 기존 UI 숨김 상태로 돌아온다.
- F1은 모달·파일 대화상자 뒤의 UI를 전환하지 않는다.

## 5. 하위 작업에서 돌아오기

**제안**
- 내보내기·가져오기·초기화의 성공 뒤에는 메뉴를 닫고 편집·감상 화면으로 복귀한다.
- 파일 선택 취소·작업 취소는 메뉴로 돌아온다. 실패는 사유를 표시한 뒤 메뉴·기존 작업으로 돌아갈 수 있게 한다.
- 옵션의 적용 없는 닫기는 메뉴로 돌아온다. 경로 적용에 성공하면 재시작 흐름으로 진행한다.

## 6. 검수

| 시나리오 | 기대 결과 |
|---|---|
| 일반 화면에서 ESC, 다시 ESC | 메뉴 열림 → 메뉴 닫힘, 종료 확인 없음 |
| 꾸미기 패널 닫힘 | 메뉴에서 파일·옵션·종료 접근 가능 |
| 메뉴에서 종료 | 추가 확인 없이 저장 후 종료 |
| 종료 전 저장 실패 | 앱 유지, 복구 선택 표시 |
| 옵션 안의 목록에서 ESC | 목록만 닫힘. 다음 ESC는 옵션→메뉴, 다음은 메뉴 닫힘 |
| UI 숨김 중 ESC·메뉴 닫기 | 메뉴만 임시 표시했다가 원래 숨김 화면으로 복귀 |
| 메뉴·팝업 닫는 클릭 | 뒤 UI·카메라로 전달되지 않음 |
