# 스튜디오 배경

> 정리일: 2026-11-03
> 구현 가능한 범위를 기준으로 쓴 초안이다. 외부 검토 전이므로 사용자가 정한 것만 확정으로 표시한다.
> 확정·제안·미정 표기를 유지한다. 화면·상태 전환은 [프로그램 플로우](ProgramFlow.md)를 참고한다.

## 1. 목적과 범위

- 게임 스튜디오(촬영모드)의 배경을 꾸미기 장면 뒤에 그대로 깔아, 게임과 비슷한 조건에서 코디를 본다.
- 배경 목록·색·3D 리소스는 설치 폴더의 데이터를 읽는다. 앱에 배경 리소스를 넣지 않는다.
- 촬영모드 자체(캡처·UI 숨김·포즈)는 이 문서의 범위가 아니다([촬영모드](PhotoMode.md)).

**확정 (2026-11-02, 사용자 요청)**
- 게임 스튜디오의 기본 배경(민트바닐라)과 스튜디오 배경 선택 목록을 앱에 적용한다.
- 캐릭터 몸의 그늘은 캐릭터 셰이더(툰 명암·헤어 그림자 메시)가 그린다. Unity 실시간 그림자가 캐릭터 위에 한 번 더 그려지지 않게 한다(5장).

## 2. 데이터

- 배경 시트 `StudioBackground`(심볼 표 `StudioBackgroundSheet`)를 읽는다. [확인] 16행.

| 필드 | 쓰임 |
|---|---|
| `Id` | 저장·표시 식별자 |
| `BackgroundName` | 표시 이름 |
| `LeftBottom`·`RightBottom`·`LeftUpper`·`RightUpper` | 화면 네 모서리 색(`#RRGGBB` 문자열) |

- 시트 행 구조가 바뀌어 읽지 못해도 앱 시작을 막지 않는다. 기본 색만 쓰고 꾸미기 창에 안내한다.

## 3. 선택과 저장

**제안 (구현함)**
- 꾸미기 창에 "배경" 폴드아웃(처음엔 접힘)을 두고 검색 드롭다운으로 고른다. 고르면 바로 바뀐다.
- 항목 표시: 이름, 보조 표시 `Id`(3D는 `Id · 3D`), 색 배경은 위·아래 색 견본.
- 목록 순서는 시트 순서다. 게임 화면의 순서(3D 배경 먼저)와 다르다.
- 기본 배경은 `BG_Gradation1`이다. 없으면 고를 수 있는 첫 행을 쓴다.
- 업적 잠금은 적용하지 않는다. 모든 공개 배경을 처음부터 고를 수 있다.
- 웹캠·웹 페이지 배경은 후보에서 뺀다.
- 개발용 3D 행은 에디터에서만 `[숨김] 이름`으로 후보에 넣는다. 일반 빌드는 저장값이 개발용 ID여도 기본 배경으로 표시한다([의상·리소스 선택](Equipment.md)의 숨김 데이터 공개 범위와 같은 원칙).

**확정 원칙 적용**
- [내보내기·가져오기](SaveLoad.md)의 확정 원칙("UI를 제외한 장면 상태 전체 저장")에 따라 배경 Id를 장면 상태(`background`)로 자동 저장·코디 JSON에 넣는다.
- 저장된 Id가 없거나 고를 수 없으면 기본 배경으로 표시하고, 저장값은 지우지 않는다(의상 미적용 선택을 유지하는 규칙과 같다).
- 배경 필드가 없는 예전 JSON은 기본 배경으로 연다. 파일 형식 버전은 올리지 않는다.

**확정 (2026-11-03)**
- 배경 선택은 꾸미기 창에서 바꾸는 편집값으로 [꾸미기 실행 취소·다시 실행](UndoRedo.md)에 포함한다. 카메라 조작·화각과 구분한다.
- [코디 초기화](Reset.md) 시 배경은 유지한다. 정상 JSON 가져오기는 파일의 배경을 복원한다.

## 4. 표시 방식

### 색 배경

**제안 (구현함)**
- 네 모서리 색을 화면에 고정된 그라데이션으로 그린다. 카메라를 돌려도 배경은 움직이지 않는다.
- 색은 sRGB 값끼리 섞는다(UI 정점색 그라데이션과 같은 방식) [추정]. 게임 스크린샷과 눈으로 비교해 비슷하다 [확인].
- 발밑에는 그림자만 받는 바닥을 둔다. 설치 폴더의 스튜디오 그림자 바닥 프리팹(`StudioPhotoMode_ShadowReceiver`, 10m×10m)을 원점 높이에 둔다. 원본 프리팹은 y = -100에 숨겨져 있다 [확인].

### 3D 배경

**제안 (구현함)**
- 시트의 배경 프리팹을 설치 폴더 번들에서 열어 원점에 둔다. 캐릭터는 원점에 선다.
- 원본 배경 셰이더를 그대로 쓴다. 이 셰이더들은 게임 전용 패스(`BG`, `SkyLit`, `ExcludeDecal`, `Decal`)만 가지므로, URP 기본 렌더러가 그리지 않는다. 앱이 카메라마다 이 패스를 그리는 렌더 패스를 끼운다. 렌더러 에셋 설정은 바꾸지 않는다.
- 3D 배경 뒤에도 시트의 네 모서리 색을 깐다. 3D 행은 모두 흰색이다.
- 카메라 먼 평면을 3000m로 늘린다(하늘 돔 반지름 수백 m). 색 배경은 100m.
- 방 배경에서 카메라가 벽 밖으로 나가면, 카메라와 캐릭터 사이를 가리는 배경 메시(벽·소품)를 숨긴다. 렌더러 범위로 판단하고 캐릭터 기준점을 감싸는 메시(바닥·하늘)는 숨기지 않는다. 게임은 배경의 레이캐스트 콜라이더로 같은 일을 하는 것으로 보인다 [추정].
- 프리팹에 들어 있는 게임 스크립트는 없는 스크립트로 남고 동작하지 않는다(경고 로그만 남는다).
- 3D 배경은 고를 때 동기로 연다. 바꾸기 전에 기존 배경을 지운다.

**[확인] 3D 배경 시험 결과(2026-11-02, 에디터 배치 + Windows 빌드)**

| 배경 | 열기 | 표시 | 남은 문제 |
|---|---|---|---|
| 벨벳 의상실 | 30~56ms | 방·소품·바닥 그림자 표시 | 벽 조명 데칼 미표시(아래) |
| 클래식 피팅룸 | 28~31ms | 방·소품 표시. 기본 거리에서 앞벽을 숨겨 안이 보인다 | — |
| 공간의 틈: 빛 | 40~55ms | 바닥·구조물 표시 | 구름 하늘(`SkyLit`)이 그려지지 않아 흰 배경이 하늘로 보인다 |
| 공간의 틈: 어둠 | 18~20ms | 하늘·구조물 표시 | 바닥이 매우 어둡다(원본과 비교 [미확인]) |

- 열기 시간은 의존 번들을 처음 여는 경우를 포함한다. 같은 실행에서 다시 고르면 더 빠르다 [추정].

**미정·알려진 제한**
- 벽 조명 데칼(`Decal` 패스, `MMN/FX/ObjectDecalLight`)은 그리지 않는다. Windows 빌드(D3D12)에서 이 패스를 그리면 앱을 닫을 때 `D3D12Core.dll`에서 접근 위반으로 죽었다 [확인: 벨벳 의상실 3회 재현, D3D11 강제 시 정상]. 원인 분석은 미정이다.
- 배경별 화면 보정(`VolumeKey`)은 적용하지 않는다. 프리팹 안의 Volume 컴포넌트도 끈다. 색감이 게임과 다를 수 있다.
- '공간의 틈: 빛'의 구름 하늘이 그려지지 않는 원인은 [미확인]이다. 게임이 전역 셰이더 값을 넣어 주는 것으로 의심한다 [추정].
- 배경 프리팹의 점광원은 원본 배경 셰이더에만 영향이 있다 [추정]. 캐릭터는 앱의 방향광 하나로 비춘다.
- 목록 아이콘 이미지(`BackgroundImagePath`)는 아직 쓰지 않는다.

## 5. 조명과 그림자

**확정 (2026-11-02, 사용자 요청)**
- 캐릭터는 Unity 그림자 맵을 받지 않는다. 캐릭터 몸의 그늘은 셰이더의 툰 명암과 헤어 그림자 메시(`Hair_Shadow`)로만 그린다.
  - 이전에는 그림자 맵이 셰이더 명암 위에 한 번 더 그려져, 턱 아래 목·머리카락 아래에 진하고 각진 그림자가 겹쳤다 [확인: 같은 구도 전후 촬영 비교].
- 캐릭터는 그림자를 드리운다. 바닥(그림자 바닥·3D 배경 바닥)에만 캐릭터 그림자가 보인다.

**제안 (구현함)**
- 방향광 그림자 세기 0.45. 게임 스튜디오 스크린샷의 옅은 바닥 그림자에 맞춘 근사다.

**미정**
- 게임 스크린샷은 그림자가 캐릭터 오른쪽 뒤로 진다. 앱은 왼쪽 뒤로 진다. 조명 방향을 게임에 맞추면 캐릭터 명암 방향도 바뀌므로 사용자 확인 후 정한다.

## 6. 검수 항목

- 첫 실행: 민트바닐라 그라데이션과 옅은 발밑 그림자가 보인다.
- 배경 드롭다운: 공개 배경 11개, 색 견본, 이름·Id 검색.
- 각 3D 배경: 표시, 회전 시 앞을 가리는 벽·소품이 숨겨지는지, 바닥 그림자.
- 배경을 바꾼 뒤 앱 재실행·JSON 내보내기·가져오기에서 배경이 복원되는지.
- 배경을 바꿔도 캐릭터·카메라 시점이 바뀌지 않는지.
- 개발용 배경 Id가 든 JSON을 일반 빌드에서 열면 기본 배경으로 보이는지.
- 3D 배경을 고른 상태로 앱을 닫아도 오류 없이 종료되는지.

## 7. 재검토 결과 (2026-11-02)

> 검토 기준: main `fb22b2e`. 아래는 코드·시트·추출 프리팹 검토 결과다. 이번에 Unity·Windows 빌드·실제 조작을 재실행한 결과가 아니다.

### 유지할 방향

- StudioBackground 시트는 exact 16행이며 DevOnly=false인 색 7개·3D 4개가 현재 목록과 일치한다. DevOnly와 웹캠·Url 제외, 게임 업적 잠금 미적용은 현재 방향에 맞는다.
- 배경을 장면 상태로 저장하고, 배경 변경만으로 캐릭터를 재조립하거나 카메라 거리·화각을 초기화하지 않는 구성이 적절하다.
- UI 숨김은 배경 폴드아웃을 포함한 꾸미기 층을 함께 숨긴다. 배경 그라데이션·3D 렌더링은 유지한다.
- 캐릭터의 Unity 그림자 받기를 끄고 바닥 그림자만 남기는 것은 이 문서의 사용자 확정 사항과 일치한다.

### 우선 수정할 구현

> 2026-11-03 구현: 아래 1~3을 반영했다(새 배경을 먼저 준비한 뒤 교체, 실패 시 이전 배경·저장·이력 유지, 저장 ID를 표시할 수 없을 때 요청 ID·사유·대체 배경 안내와 가져오기·시작 복원의 부분 복원 안내, `ID - 이름` 표기). 실제 리소스 누락 상황의 조작 확인은 하지 않았다.

1. **배경 적용 실패 시 이전 정상 배경을 유지한다.** 현재 StudioBackground.Apply는 새 리소스를 읽기 전에 Clear와 CurrentId 변경을 한다. 리소스 누락 시 이전 배경은 사라지고, SetBackground는 실패한 CurrentId도 장면·자동 저장에 확정한다. 드롭다운은 현재 ID의 재선택을 무시하므로 같은 항목을 바로 재시도할 수도 없다. 새 배경을 별도로 준비하고 성공한 뒤 교체·저장하는 방식으로 바꿀 것을 제안한다. 시작 복원의 대체 표시와 편집 중 새 선택 실패를 구분한다.
2. **누락·제한 ID의 대체 표시 사유를 알린다.** 현재 Resolve는 없는 ID·일반 빌드의 DevOnly ID를 오류 정보 없이 기본 배경으로 바꿔 표시한다. 선택 UI도 실제 표시 중인 기본 배경만 보여 준다. 저장 ID를 보존하는 점은 맞지만, 요청한 ID·실제 대체 배경·누락/공개 제한 사유가 구분되지 않는다. SaveLoad.md의 부분 복원 안내·취소 원칙에 연결한다. 필드가 없는 구버전 파일의 정상 기본값 적용은 오류로 안내하지 않는다.
3. **표시 형식을 공통 규칙으로 맞춘다.** 현재 배경은 이름을 앞에 두고 ID를 보조 열로 표시한다. 에디터 항목도 `[숨김] 이름`이다. 기존 공통 규칙인 `ID - 이름`·`[숨김] ID - 이름`에 맞추고, 3D 여부와 색 견본은 별도 보조 표시로 둔다.

### 기획 보강 제안

- 당시 배경 실행 취소 포함 권장안은 2026-11-03 꾸미기 이력 정책으로 채택했다. 이력 구현 시 한 번의 정상 배경 선택을 한 항목으로 기록한다. 실패한 선택은 기록하지 않는다. 현재 실행 취소 기능 자체는 후속 구현이며 배경 undo 동작을 확인한 것은 아니다.
- 당시 코디 초기화 시 배경 유지 권장안은 2026-11-03에 채택했다. 최신 기준은 Reset.md다.
- Volume·구름 하늘·벽 데칼을 완전히 재현하지 않으므로 게임과 동일한 색감·조명이라고 보장하지 않는다. 코디 비교에는 동일한 배경·조명·화각을 유지한다.

### 추가로 확인할 렌더링

- '공간의 틈: 빛'의 구름 미표시는 기존 기록에 남은 문제다. 원인을 전역 셰이더 값 부족으로 확정하지 않는다. 현재 전용 패스는 BG·ExcludeDecal·SkyLit을 같은 AfterRenderingOpaques 단계에 그린다. Frame Debugger에서 후속 그라데이션 스카이박스와의 순서, 구름 재질의 ZWrite·ZTest·블렌딩을 함께 확인한다. 깊이를 쓰지 않는 구름이 뒤의 스카이박스로 덮일 가능성은 검증 후보이며 재현한 결함이 아니다.
- 벽 숨김은 카메라에서 기준점으로 향하는 한 선과 Renderer.bounds의 교차를 쓰는 근사다. 광각·상하각·팬 이동에서 캐릭터 일부가 가려지거나 큰 메시가 과하게 사라지는지 확인한다.
- 벨벳 의상실 프리팹에 점광원 3개, 클래식 피팅룸에 2개가 있다. 생성 시 Volume은 끄지만 Light는 별도 분리하지 않는다. 대체 몸 셰이더는 GetMainLight만 사용하나 원본 머리·눈 셰이더까지 배경 변경의 영향이 없는지 실제 색 비교로 확인한다. 배경 조명을 캐릭터와 분리했다고 단정하지 않는다.
- 공개 3D 4종을 반복 선택한 뒤 색 배경으로 돌아오는 조작, 0.5x·1x·3x 전환, UI 숨김·복귀, 재실행 복원과 D3D12 종료를 함께 검수한다.
