# 스튜디오 배경

> 정리일: 2026-11-14
> 구현 가능한 범위를 기준으로 쓴 초안이다. 외부 검토 전이므로 사용자가 정한 것만 확정으로 표시한다.
> 확정·제안·미정 표기를 유지한다. 화면·상태 전환은 [프로그램 플로우](ProgramFlow.md)를 참고한다.

## 1. 목적과 범위

- 게임 스튜디오(촬영모드)의 배경을 꾸미기 장면 뒤에 그대로 깔아, 게임과 비슷한 조건에서 코디를 본다.
- 배경 목록·색·3D 리소스는 설치 폴더의 데이터를 읽는다. 앱에 배경 리소스를 넣지 않는다.
- 촬영모드 자체(캡처·UI 숨김·포즈)는 이 문서의 범위가 아니다([촬영모드](PhotoMode.md)).

**확정 (2026-11-02, 사용자 요청)**
- 게임 스튜디오의 기본 배경(민트바닐라)과 스튜디오 배경 선택 목록을 앱에 적용한다.
- 캐릭터 몸의 그늘은 캐릭터 셰이더(툰 명암·헤어 그림자 메시)가 그린다. Unity 실시간 그림자가 캐릭터 위에 한 번 더 그려지지 않게 한다(5장).

## 2. 데이터

- 배경 시트 `StudioBackground`(심볼 표 `StudioBackgroundSheet`)를 읽는다. [확인] 16행.

| 필드 | 쓰임 |
|---|---|
| `Id` | 저장·표시 식별자 |
| `BackgroundName` | 표시 이름 |
| `LeftBottom`·`RightBottom`·`LeftUpper`·`RightUpper` | 화면 네 모서리 색(`#RRGGBB` 문자열) |
| `BackgroundPrefabPath` | 3D 배경 프리팹 목록. 비어 있으면 색 배경 |
| `DevOnly` | 개발용 행 |
| `UseWebCamTexture`·`Url` | 웹캠·웹 페이지 배경 |
| `UnlockType`·`UnlockTypeParam`·`HintText` | 게임의 업적 잠금 |

| `VolumeKey`·`VolumeGroupName` | 배경별 환경 볼륨 키·사용자 그룹(8장) |

- 시트 행 구조가 바뀌어 읽지 못해도 앱 시작을 막지 않는다. 기본 색만 쓰고 꾸미기 창에 안내한다.

## 3. 선택과 저장

**제안 (구현함)**
- 꾸미기 창에 "배경" 폴드아웃(처음엔 접힘)을 두고 검색 드롭다운으로 고른다. 고르면 바로 바뀐다.
- 항목 표시: 이름, 보조 표시 `Id`(3D는 `Id · 3D`), 색 배경은 위·아래 색 견본.
- 목록 순서는 시트 순서다. 게임 화면의 순서(3D 배경 먼저)와 다르다.
- 기본 배경은 `BG_Gradation1`이다. 없으면 고를 수 있는 첫 행을 쓴다.
- 업적 잠금은 적용하지 않는다. 모든 공개 배경을 처음부터 고를 수 있다.
- 웹캠·웹 페이지 배경은 후보에서 뺀다.
- 개발용 3D 행은 에디터에서만 `[숨김] 이름`으로 후보에 넣는다. 일반 빌드는 저장값이 개발용 ID여도 기본 배경으로 표시한다([의상·리소스 선택](Equipment.md)의 숨김 데이터 공개 범위와 같은 원칙).

**확정 원칙 적용**
- [내보내기·가져오기](SaveLoad.md)의 확정 원칙("UI를 제외한 장면 상태 전체 저장")에 따라 배경 Id를 장면 상태(`background`)로 자동 저장·코디 JSON에 넣는다.
- 저장된 Id가 없거나 고를 수 없으면 기본 배경으로 표시하고, 저장값은 지우지 않는다(의상 미적용 선택을 유지하는 규칙과 같다).
- 배경 필드가 없는 예전 JSON은 기본 배경으로 연다. 파일 형식 버전은 올리지 않는다.

**확정 (2026-11-03)**
- 배경 선택은 꾸미기 창에서 바꾸는 편집값으로 [꾸미기 실행 취소·다시 실행](UndoRedo.md)에 포함한다. 카메라 조작·화각과 구분한다.
- [코디 초기화](Reset.md) 시 배경은 유지한다. 정상 JSON 가져오기는 파일의 배경을 복원한다.

## 4. 표시 방식

### 색 배경

**제안 (구현함)**
- 네 모서리 색을 화면에 고정된 그라데이션으로 그린다. 카메라를 돌려도 배경은 움직이지 않는다.
- 색은 sRGB 값끼리 섞는다(UI 정점색 그라데이션과 같은 방식) [추정]. 게임 스크린샷과 눈으로 비교해 비슷하다 [확인].
- 발밑에는 그림자만 받는 바닥을 둔다. 설치 폴더의 스튜디오 그림자 바닥 프리팹(`StudioPhotoMode_ShadowReceiver`, 10m×10m)을 원점 높이에 둔다. 원본 프리팹은 y = -100에 숨겨져 있다 [확인]. 바닥 재질은 앱 셰이더(`MobiAtelier/ShadowReceiver`)로 바꾼다. 원본 셰이더(`MMN/MMN_ShadowOnly`)는 앱의 소프트 그림자 필터를 쓰지 않아 그림자 맵 계단이 보였다 [확인].

### 3D 배경

**제안 (구현함)**
- 시트의 배경 프리팹을 설치 폴더 번들에서 열어 원점에 둔다. 캐릭터는 원점에 선다.
- 원본 배경 셰이더를 그대로 쓴다. 이 셰이더들은 게임 전용 패스(`BG`, `SkyLit`, `ExcludeDecal`, `Decal`)만 가지므로, URP 기본 렌더러가 그리지 않는다. 앱이 카메라마다 이 패스를 그리는 렌더 패스를 끼운다. 렌더러 에셋 설정은 바꾸지 않는다.
- 3D 배경 뒤에도 시트의 네 모서리 색을 깐다. 3D 행은 모두 흰색이다.
- 카메라 먼 평면을 3000m로 늘린다(하늘 돔 반지름 수백 m). 색 배경은 100m.
- 방 배경에서 카메라가 벽 밖으로 나가면, 카메라와 캐릭터 사이를 가리는 배경 메시(벽·소품)를 숨긴다. 렌더러 범위로 판단하고 캐릭터 기준점을 감싸는 메시(바닥·하늘)는 숨기지 않는다. 게임은 배경의 레이캐스트 콜라이더로 같은 일을 하는 것으로 보인다 [추정].
- 프리팹에 들어 있는 게임 스크립트는 없는 스크립트로 남고 동작하지 않는다(경고 로그만 남는다).
- 3D 배경은 고를 때 동기로 연다. 바꾸기 전에 기존 배경을 지운다.

**[확인] 3D 배경 시험 결과(2026-11-02, 에디터 배치 + Windows 빌드)**

| 배경 | 열기 | 표시 | 남은 문제 |
|---|---|---|---|
| 벨벳 의상실 | 30~56ms | 방·소품·바닥 그림자 표시 | 벽 조명 데칼 미표시(아래) |
| 클래식 피팅룸 | 28~31ms | 방·소품 표시. 기본 거리에서 앞벽을 숨겨 안이 보인다 | — |
| 공간의 틈: 빛 | 40~55ms | 바닥·구조물·구름·하늘·바닥 반사 표시 | 반사 바닥이 게임보다 어둡고 파랗다(아래) |
| 공간의 틈: 어둠 | 18~20ms | 하늘·구조물·바닥 반사 표시 | 반사 바닥이 게임보다 조금 붉다(앱 45,12,27 ↔ 게임 26,14,32) |

- 열기 시간은 의존 번들을 처음 여는 경우를 포함한다. 같은 실행에서 다시 고르면 더 빠르다 [추정].

**미정·알려진 제한**
- 벽 조명 데칼(`Decal` 패스, `MMN/FX/ObjectDecalLight`)은 그리지 않는다. Windows 빌드(D3D12)에서 이 패스를 그리면 앱을 닫을 때 `D3D12Core.dll`에서 접근 위반으로 죽었다 [확인: 벨벳 의상실 3회 재현, D3D11 강제 시 정상]. 원인 분석은 미정이다.
- 배경별 환경 볼륨(`VolumeKey`)은 8장대로 적용한다. 프리팹 안의 URP Volume(Beautify 후처리)은 끈다.
- '공간의 틈: 빛'의 구름(`MMN/CutScene/Sky_Clouds`, 큐 2601, 깊이 안 씀)은 불투명 단계에서 그린 뒤 그라데이션 스카이박스가 덮어 보이지 않았다. 반투명 큐를 스카이박스 다음 단계로 나눠 그려 해결했다 [확인: 2026-11-14 배치 촬영].
- 게임의 파란 하늘은 NaoZone 씬 번들의 스카이박스 재질(`Environment/Skybox/NaoZone/NaoZone_Skybox_Sunny_RE.mat`, `MMN/BG/Sky_Re`)로 보인다. 시험으로 이 재질을 스카이박스로 쓰면 하늘이 파랗게 나온다 [확인: 배치 촬영]. 이 셰이더는 전역 하늘 값(`_Global_SkyColor*`)을 읽지 않는다 [확인: 전역 값을 빨강으로 바꿔도 그대로]. 볼륨 Skybox 항목 이름이 재질 속성 이름(`_SkyColorTop·Middle·Bottom`, `_SkyPosition1~4`, `_SunDisk`, `_SunGlowDisk`, `_SunGlowColor`)과 같고, 볼륨 값을 재질에 넣으면 하늘색이 (143,177,202)로 게임 (152,185,217)에 가까워진다(재질 기본값은 203,230,250) [확인: 배치 촬영 픽셀 비교]. 게임은 볼륨 값을 현재 스카이박스 재질에 넣는 것으로 보인다 [추정]. **구현함(2026-11-14, 사용자 결정):** 3D 배경의 볼륨에 하늘 색이 있으면 이 재질의 복제본을 스카이박스로 쓰고 볼륨 하늘 값을 넣는다(`EnvironmentVolume.ApplySky`). 볼륨이 없거나 재질을 열지 못하면 시트 색 그라데이션을 쓴다. 스튜디오 배경 시트에는 씬 필드가 없고 `PhotoStudio` 맵을 참조하는 시트도 없어, 스튜디오는 플레이어가 있는 맵 위에 배경을 띄우는 것으로 보인다 [추정: 게임 코드 `StudioBackgroundSystem` 은 색 그라데이션 패스만 가진다]. 배경과 씬을 잇는 데이터가 없어 씬 번들은 읽지 않는다.
- 구름 셰이더(`MMN/CutScene/Sky_Clouds`)는 `_Global_CloudColor`~`4`·`_Global_GILightMulti`·주광 색·앰비언트(SH)를 쓴다 [확인: 설치 폴더 셰이더의 변수 이름 표]. 구름 색 2~4 를 넣어 구름이 게임처럼 희어졌다(2026-11-14 구현). NaoZone 볼륨의 구름 색은 시각과 관계없는 값이다 [확인].
- 구름 그늘은 게임이 더 푸르다. 앰비언트를 NaoZone 씬 값(L0 0.66, 0.83, 1.03)으로 바꾸면 게임에 가까워지지만, 스튜디오가 어느 맵의 앰비언트를 쓰는지 데이터가 없어 넣지 않았다. 하늘에서 앰비언트를 계산(DynamicGI)하면 하늘 색이 검정인 방 배경의 앰비언트도 검게 바뀌어 되돌렸다 [확인: 촬영]. 캐릭터(앱 셰이더·원본 얼굴)는 앰비언트 영향이 없다 [확인: 촬영].
- 배경 셰이더 식(2026-11-14, 설치 폴더 셰이더 디스어셈블) [확인]: SimpleLit 밝기 = 바탕색 × (정점 앰비언트 SH × `_Global_GILightMulti` + 하늘 항(`_Global_SkyColorTop`) + 주광 × 구름 그림자 × 라이트 레이어 일치). 구름 그림자 = saturate(노이즈 + `_Global_CloudDensity`)^`_Global_CloudEdgeHardness`(밀도 0.9 면 거의 1). PlanarReflection = lerp(같은 조명의 바닥, 반사 × `_ReflectionColor`, `_ReflectionRatio`) 에 `_ReflectionAmbient` 보정.
- 라이트 프로브(2026-11-14 구현): 볼륨 키와 이름이 같은 GeoData(`GeoData/<키>/GeoData`)가 그 키를 기본 볼륨으로 쓰면 그 `LightProbeAssetPath` 를 넣는다. 공간의 틈은 `NaoZone` GeoData 의 프로브 8개. 벽이 앱 149 → 167(게임 180), 색도 중립이 됐다 [확인: 배치·빌드 촬영]. 벨벳 의상실 GeoData(`FashionShop_BG`)는 프로브가 없고 씬 앰비언트만 있다. 씬 앰비언트는 씬 번들을 열어야 읽혀 넣지 않았다(넣어도 벨벳 의상실 변화는 선형 1.07~1.38배로 작다 [확인: 시험]).
- 바닥 반사(2026-11-14 구현): 게임 스크립트 `PlanarReflections` 는 반사 카메라로 레이어 26(스튜디오 배경 전체)을 그려 `_PlanarReflectionTexture` 에 넣고 `_LowOptionEnable` 을 0 으로 둔다 [확인: 프리팹 값·셰이더 변수 이름 표]. 앱은 불투명 전 렌더 패스(`StudioReflectionPass`)에서 카메라를 바닥 평면으로 뒤집어 캐릭터·배경·하늘·구름을 그린다. 반사 바닥 자신은 렌더링 레이어로 뺀다. 컬링은 본 카메라 결과를 쓴다. 클립 평면은 바닥 위 +0.04 (게임 값 -0.04 는 부호 규칙 [미확인], 그대로 쓰면 무늬 경계에 점선 자국).
- 반사 끔 상태(`_LowOptionEnable` 1)는 재질의 구운 큐브맵을 비율 0.2 로 쓴다. 게임 그래픽 옵션 1단계(Low)는 반사 카메라를 건너뛴다(`planarReflectionQuality.skipRendering`) [확인].
- 공간의 틈: 빛 반사 바닥은 게임 구도에 맞춘 촬영에서 앱이 sRGB 약 1.3배 어둡다(앱 136~154 ↔ 게임 182~197), 벽은 약 1.1배 [확인: 라이트 프로브 적용 후]. 반사에서 하늘을 빼면 밝아지지만 하늘색이 사라져 하늘을 넣는다. 원인 [미확인].
- 배경 프리팹의 점광원은 원본 배경 셰이더에만 영향이 있다 [추정]. 캐릭터는 앱의 방향광 하나로 비춘다.
- 목록 아이콘 이미지(`BackgroundImagePath`)는 아직 쓰지 않는다.

## 5. 조명과 그림자

**확정 (2026-11-02, 사용자 요청)**
- 캐릭터는 Unity 그림자 맵을 받지 않는다. 캐릭터 몸의 그늘은 셰이더의 툰 명암과 헤어 그림자 메시(`Hair_Shadow`)로만 그린다.
  - 이전에는 그림자 맵이 셰이더 명암 위에 한 번 더 그려져, 턱 아래 목·머리카락 아래에 진하고 각진 그림자가 겹쳤다 [확인: 같은 구도 전후 촬영 비교].
- 캐릭터는 그림자를 드리운다. 바닥(그림자 바닥·3D 배경 바닥)에만 캐릭터 그림자가 보인다.

- 안개: 안개 색·시작·끝 거리를 Unity 선형 안개로 켠다 [추정: 게임 안개 방식과의 대응].
- 전역 셰이더 값: 하늘 색·위치·해, 구름 색·밀도·크기·경계, GI 색(`_Global_GILightMulti`), 밤낮·비·눈, 높이 안개·DimFog, 캐릭터 조명·실루엣. 이름은 볼륨 필드와 게임 셰이더 전역 이름의 대응이다 [추정].
- 캐릭터 빛 색: 캐릭터 조명 색의 알파가 0 보다 크면 그 색, 아니면 주광 색 × 세기 [확인: 원본 얼굴 셰이더가 이렇게 움직인다. 공간의 틈: 어둠에서 둘 중 하나만 빼면 얼굴이 남은 쪽 색으로 물들고, 둘 다 빼야 기본색이었다. 피팅룸의 주광 세기 0.4 는 얼굴 밝기에 영향이 없었다]. 앱 셰이더(몸·의상·헤어)도 같은 색을 쓰게 맞췄다.
- 캐릭터 빛 방향: 주광 방향을 따른다(볼륨이 있으면 볼륨 방향, 색 배경은 앱 기본 35°·155°). 원본 캐릭터 셰이더가 주광 방향을 쓴다 [확인: 몸·의상에 원본 셰이더를 임시로 쓰고 볼륨 회전 유무로 촬영하면 명암이 바뀌었다]. 사용자 결정(2026-11-12): 게임 데이터에 맞춘다.
- 전역 텍스처: 배경 프리팹의 `EnvironmentConfig`(게임 스크립트라 앱에서 돌지 않는다)가 넣는 `_Global_Texture`(노이즈, 배경 원본 셰이더가 씀)·`_Global_LightRampTexture`·`_Global_Weapon_Texture`·`_Global_Wet_Texture` 를 3D 배경을 처음 확정할 때 설치 폴더에서 읽어 넣는다. 벨벳 의상실·클래식 피팅룸 프리팹의 값이 같다 [확인]. 공간의 틈 프리팹에는 `EnvironmentConfig` 가 없다.
- 색 배경: 볼륨 키가 없다. 설치 폴더의 `PhotoStudio` 볼륨은 별도 가상 방 맵(`GeoData/PhotoStudio`)의 것이고 시트에서 참조하지 않아 쓰지 않는다 [확인].

### 8.3 적용하지 않은 것

- 화면 후처리 중 블룸·채도·대비. 노출은 배경 조명 배수로 근사한다(8.1). 발광·하늘 같은 조명 없는 면은 노출을 받지 않는다.
- 앰비언트 그라데이션(`PostProcessing` 섹션, 원본 `MMN_PP_AmbientGradient` 전체 화면 패스). 게임에서 켜는 조건 [미확인].
- 접촉 그림자(`_Global_ContactShadowStrength`·`_Global_CharacterDirectionAndHeight`·`_Global_pos`): 배경 바닥 셰이더가 캐릭터 발밑을 어둡게 한다. 값을 넣으면 피팅룸·공간의 틈 바닥의 발밑이 어두워지는 것을 시험 촬영으로 확인했다. 게임은 이 값을 실행 중에 정하고 데이터에 없어, 게임 스크린샷과 비교해 값을 정한 뒤 도입한다.
- SelectiveSSAO, 바람(`WindSpeed` → `_Global_WindUV` 변환식 [미확인]), 하늘 Unlit 색·스크롤, 카메라 먼 평면·LOD, 환경음.

### 8.4 촬영 비교 결과 (2026-11-12, 배치 촬영)

- 벨벳 의상실: 방이 전체적으로 어두워지고 바닥 그림자 방향이 볼륨 주광을 따른다. 캐릭터는 회색 0.9 빛으로 조금 어두워진다.
- 클래식 피팅룸: 주광 0.4 로 방이 어두워진다. 캐릭터는 같은 0.9 빛이다.
- 공간의 틈: 빛: 바닥이 밝고 푸른 안개를 띤다. 구름은 2026-11-14 렌더 순서 수정 뒤 보인다(하늘색·바닥 반사는 4장 제한).
- 공간의 틈: 어둠: 얼굴·몸·의상이 함께 분홍빛을 띤다. 볼륨 적용 전에는 얼굴만 분홍으로 물드는 문제가 있었다.
- 캐릭터 빛 방향을 볼륨에 맞춘 뒤: 3D 배경에서 캐릭터 명암 방향이 배경마다 바뀐다(벨벳 의상실·피팅룸은 옆에서 비춘다). 색 배경은 그대로다.
- 게임 화면과 같은지는 [미확인]이다. 같은 배경의 게임 스튜디오 스크린샷과 비교해야 한다.
- 시험: 스모크 테스트 `-maBackgrounds` 에 볼륨 키·주광·안개를 로그로 남기고, `-maNoVolume`(볼륨 없이)·`-maVolumeSkip 섹션.필드;…`(일부 값 제외)로 비교한다.
