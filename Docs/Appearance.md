# 캐릭터 외형 선택 기획

> 정리일: 2026-11-02
> 사용자 제공 마비노기 모바일 환생 화면을 선택 범위의 기준으로 삼는다.
> 확정·제안·미정을 구분한다. 기능 지원 요구가 확정됐다는 뜻이며 구현·렌더링 완료를 의미하지 않는다.

## 기본 원칙

**확정**
- 첨부 환생 화면에 나온 외형 항목을 모두 선택·편집할 수 있게 한다. 일부 항목을 임의로 후속 기능으로 제외하지 않는다.
- 큰 카테고리는 폴드아웃으로 열고 닫는다. 항목 후보는 이름을 표시하는 검색 가능한 드롭다운으로 선택한다.
- 환생 화면의 아이콘·썸네일 격자 배치는 필수로 재현하지 않는다. 텍스트 선택 UI를 기준으로 한다.
- 의상 선택에도 같은 폴드아웃·검색 드롭다운 원칙을 적용한다([창·꾸미기 UI](WindowAndCustomizationUI.md), [의상](Equipment.md)).
- **사용자 결정 2026-11-02**: 피부·헤어·눈 색은 게임 색 시트에 있는 색 중에서 고른다(아래 "외형 색"). 컬러피커·#RRGGBB 자유 입력은 의상 염색에 쓴다([염색 기획](Dye.md)). 이전의 "외형 색도 컬러피커로 자유 편집" 확정을 대체한다.

## 선택·편집 범위

아래의 지원 항목은 모두 **확정**이다. 조작 방식에서 제안으로 표시한 부분과 세부 수치 범위는 별도로 정한다.

| 항목 | 편집 내용 | 조작 방식 |
|---|---|---|
| 성별 | 남성·여성 | 검색 가능한 드롭다운 |
| 체형 | 게임에서 제공하는 체형 종류 | 검색 가능한 드롭다운 |
| 키 | 키 조절값 | 슬라이더·수치 입력 제안. 범위·단위는 데이터 확인 후 결정 |
| 나이 | 캐릭터 나이 | 유효한 나이 목록의 검색 가능한 드롭다운 제안. 범위는 데이터 확인 후 결정 |
| 피부색 | 몸·얼굴의 피부색 | 색 시트 행의 검색 가능한 드롭다운(색 견본·HEX 표시) |
| 헤어 | 헤어스타일 | 검색 가능한 드롭다운 |
| 헤어 색상 | 선택한 헤어의 색상 | 색 시트 행의 검색 가능한 드롭다운(투톤은 견본 2개) |
| 눈 | 눈 모양 | 검색 가능한 드롭다운 |
| 눈 색상 | 눈의 색상 | 색 시트 행의 검색 가능한 드롭다운 |
| 입 | 입 모양 | 검색 가능한 드롭다운 |
| 얼굴형 | 얼굴 형태 | 검색 가능한 드롭다운 |
| 얼굴꾸밈 | 점·흉터·홍조·주근깨 등 | 검색 가능한 드롭다운 |
| 눈장식 | 안경 등 | 검색 가능한 드롭다운 |
| 몸꾸밈 | 문양·문신 등 | 검색 가능한 드롭다운 |

- 키처럼 연속 값을 편집하는 항목까지 후보형 드롭다운으로 바꾸라는 의미는 아니다. 키의 조작 방식은 위 제안 상태로 유지한다.

### 외형 색

**확정 (사용자 결정 2026-11-02)**: 피부·헤어·눈 색은 게임 데이터에 근거한 색 목록에서 고른다.

| 항목 | 근거 시트 | 적용 값 | 후보 수 [확인] |
|---|---|---|---|
| 피부색 | CharacterSkinColor (36행) | ColorCode → 피부 슬롯 Skin | 18 (꾸미기 숨김 18행 제외) |
| 헤어 색상 | CharacterHairColor (100행) | ColorCode1 → Hair, 투톤 헤어는 ColorCode2 → Hair1 | 67 (한 가지 색 41 + 투톤 26) |
| 눈 색상 | CharacterEyeColor (60행) | ColorCode → Eye | 25 |

- 후보는 시트의 HideOnCustomize가 아닌 행이다. 숨김 행(NPC·프리셋용 "기본NN" 등)은 현재 선택일 때만 흐리게 남긴다.
- 후보 이름은 시트 DisplayName, 보조 표시는 HEX다. HEX로도 검색된다.
- 해금 조건(UnlockedByRebirth·UnlockedByConsumable)으로 후보를 잠그지 않는다.
- 투톤 색을 한 가지 색 헤어에 고르면 첫 색만 보인다. 후보는 흐리게 "투톤 헤어용"으로 표시하되 고를 수는 있다.
- 투톤 헤어(CharacterHair.HairType = TwoColor, 16행)에 한 가지 색을 고르면 두 번째 영역도 첫 색으로 칠한다 [추정: 한 가지 색 행의 ColorCode2는 모두 #000000].
- 입 색은 다루지 않는다(사용자 결정 2026-11-01).
- 손바닥 색(ColorCode_Palm → Skin_Details 슬롯)은 연결을 확인하지 못해 원본 값을 유지한다 [미확인].
- 예전 JSON의 외형 사용자 색(appearance.colors)은 계속 적용하고 "사용자 지정 색"으로 표시한다. 시트 색을 고르면 지운다.
- 스크린샷의 나이 20은 현재 선택값이다. 최솟값·최댓값을 뜻하지 않는다. 체형·얼굴형 등도 화면 한 장에 보인 후보만으로 전체 목록을 제한하지 않는다.
- 얼굴꾸밈·눈장식·몸꾸밈의 없음 항목도 선택할 수 있게 한다. 동시에 선택할 수 있는 개수와 중첩 규칙은 데이터 확인 후 결정한다.
- 눈장식은 눈썹과 다른 항목이다. 첨부 화면의 눈장식 선택은 안경 등의 선택을 뜻한다.
- **확정**: 공개 대상의 상품·해금 외형은 구매·해금 조건 없이 선택한다. `HideOnCustomize` 등으로 숨김 판정된 항목과 시트 없는 모델은 `UNITY_EDITOR`에서만 제공한다. 상세 판정과 ID 표기는 Equipment.md를 따른다.

## 카테고리 배치

**확정 (사용자 결정 2026-11-02)**
- 외형은 "외형" 폴드아웃 하나로 묶는다. 의상 카테고리는 [의상 기획](Equipment.md)을 따른다.
- "외형" 안의 순서: 성별 → 체형 → 나이 → 얼굴형 → 헤어스타일 → 눈 모양 → 입 모양.
- 색 항목은 해당 모양 항목 바로 아래에 둔다(2026-11-02 구현): 피부색은 나이 다음, 헤어 색상은 헤어스타일 다음, 눈 색상은 눈 모양 다음.
- 항목 줄은 폴드아웃 제목 글자와 같은 위치에서 시작하도록 들여쓴다.

**제안**
- 아직 구현하지 않은 외형 항목(키, 얼굴꾸밈·눈장식·몸꾸밈)도 같은 "외형" 폴드아웃에 넣는다.

- 여러 폴드아웃을 동시에 열 수 있게 하는 것을 제안한다. 하나를 열 때 다른 카테고리를 반드시 닫는 아코디언으로 한정하지 않는다.
- 접기·펼치기는 표시만 바꾼다. 선택값·색상·착용 상태를 바꾸지 않는다.
- 나를 보기·무작위 외형·무작위 의상 등 주변 버튼은 선택 항목과 별개다. 첨부 화면을 근거로 해당 버튼의 기능까지 자동 확정하지 않는다.

## 외형 변경과 기존 선택

**기존 확정 사항**
- 성별·나이·체형 등을 바꿔 의상을 표시할 수 없게 되어도 의상 선택 ID와 염색값은 유지한다. 상세는 [의상 기획](Equipment.md)을 따른다.
- 최초 실행의 남녀 기본 외형 프리셋 무작위 선택과 마지막 작업 복원은 [시작 설정](Startup.md)의 정책을 유지한다. 이 문서는 편집 가능한 범위를 추가한다.
- 외형의 편집값은 [저장·불러오기](SaveLoad.md)의 장면 상태에 포함한다. 폴드아웃 상태는 UI 설정으로 구분한다.

**연동 처리 확정 (2026-11-02)**
- 성별·나이·체형·얼굴형 변경으로 다른 외형 파츠의 재해석이 필요하면 기존 논리 선택 ID와 사용자 색을 가능한 한 보존한다.
- 같은 이름의 체형·얼굴형별 데이터 행은 논리 후보로 묶는다. 내부 변형 행을 중복 후보로 나열하지 않는다.
- 새로운 선택의 로딩 실패는 기존 정상 선택과 장면을 유지한다. 정상적인 호환 불가와 파일 읽기 실패는 구분한다.
- 호환 가능한 파츠는 선택 ID와 사용자 색을 유지한다. 머리·눈·입·헤어 등 기본 외형에 필요한 파츠가 호환되지 않으면 현재 성별·나이·체형에 맞는 공개된 기본값으로 표시한다.
- 자동 대체 시 이전 논리 선택 ID·색상과 적용 조건을 별도로 보관한다. 호환 조건으로 돌아오면 이전 선택을 복원한다. 사용자가 해당 파츠를 직접 새로 고르면 보관했던 이전 선택을 지워 이후 편집을 덮어쓰지 않는다.
- 얼굴꾸밈·몸꾸밈·눈장식처럼 제거 가능한 장식은 선택·색상을 유지하고 미출력·사유를 표시한다.
- 자동 대체·미적용 재평가는 원인 외형 변경과 같은 실행 취소 단위로 처리한다. JSON·자동 저장은 보관한 선택과 현재 적용값을 함께 복원한다.
- 공개된 호환 기본값도 준비하지 못하면 변경을 확정하지 않고 기존 정상 장면을 유지한다. 숨김 모델을 빌드의 대체값으로 사용하지 않는다.

## 데이터 연결과 검증

- 기존 검토에는 성별·체형·헤어·눈·입·얼굴형의 데이터 근거가 있다. 키·나이·얼굴 맞춤에는 추가 해석·렌더링 검증이 필요하다([구현 가능성 검토](FeasibilityReview.md)).
- 얼굴꾸밈은 CharacterFaceTattoo(41행), 몸꾸밈은 CharacterBodyTattoo(27행)에 표시 이름·MinAge·성별/어린 외형별 모델 참조가 있다. 행 존재와 필드를 확인했으며 실제 렌더링·중첩·색상 연결은 추가로 검증한다.
- 눈장식은 CharacterCustomizeEyeDeco(6행)가 CostumeRewardPresetSheetId를 참조한다. 보상 프리셋에는 해당 키와 Fashion_Glasses/Fashion_Glasses_01 참조·색상값이 있으나 추출 필드가 _p0·_f1 등으로 표시돼 있어 정확한 스키마 대응을 확인해야 한다.
- 눈장식이 의상·액세서리 데이터와 연결된다면 같은 선택을 서로 다른 상태로 중복 저장하지 않는 것을 제안한다. 실제 부위 대응은 아직 확정하지 않는다.
- 스크린샷만으로 모든 항목의 조립 방식·선택 개수·색상 지원·성별 및 나이 호환성을 확인했다고 쓰지 않는다.
- 기술상 막히는 항목은 지원 요구를 삭제하지 않고, 원인과 필요한 검증을 기록한다.

## 남은 결정

- 미구현 외형 항목(키·색상·꾸밈)의 "외형" 폴드아웃 안 위치.
- 키·나이의 유효 범위·단위·최종 조작 방식.
- 얼굴꾸밈·눈장식·몸꾸밈의 선택 개수·중첩·색상 편집 범위.
