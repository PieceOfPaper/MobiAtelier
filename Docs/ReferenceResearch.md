# 캐릭터 꾸미기 도구 레퍼런스 조사

> 조사일: 2026-11-01
> 대상: MobiAtelier — 마비노기 모바일 설치 폴더의 리소스를 읽는 Unity 기반 Windows용 캐릭터 꾸미기 도구.
> 목적: 외형·의상·염색 미리보기 도구의 사용 흐름을 비교하고, MobiAtelier의 기능과 개발 우선순위를 제안한다.

현재 확정 사양은 [프로그램 플로우](ProgramFlow.md)와 [README의 항목별 기획서](../README.md#기획서)를 따른다. 아래 내용은 당시의 레퍼런스 조사·초기 제안 기록이며, 이후 확정된 단일 꾸미기 창·전체 장면 JSON 저장 등의 사양을 대체하지 않는다.

## 1. 조사 범위와 표기

- **확인 내용**: 서비스 자체의 공개 페이지·도움말·개발자 문서에서 확인한 기능이다. 모든 기능을 직접 실행하거나 렌더링 품질을 검증한 것은 아니다.
- **적용 제안**: 확인 내용을 바탕으로 MobiAtelier에 제안하는 기획이다. 별도 합의 전까지 확정 요구사항이나 구현 완료 항목으로 취급하지 않는다.
- Windows 빌드와 사용자 설치본 활용은 현재 프로젝트 방향이다. 레퍼런스의 웹 서비스·계정 연동·게임 연동 구조까지 그대로 채택하는 것은 아니다.
- 마비노기 온라인과 마비노기 모바일은 별개 게임이다. 종족·염료·장비 제한·캐릭터 조회 방식 등을 그대로 옮기지 않는다.
- 과거 후보로 언급된 MabiLabo는 이번 조사에서 충분한 1차 자료를 확인하지 못했으므로 비교 대상에서 제외한다.

## 2. 레퍼런스 비교

| 레퍼런스 | 확인한 핵심 기능 | 참고 목적 |
|---|---|---|
| 마비노기 캐릭터 시뮬레이터 | 외형 설정, 의상 검색·염색, 아이템 보관, 이미지·GIF·캐릭터 저장 | 부위별 편집의 기본 흐름 |
| Prilus Mabi Tool | 그림 목록, 색상 코드·즐겨찾기, 되돌리기, 부분 초기화, 저장·공유 | 탐색·염색·편집 편의성 |
| Wowhead Transmog | 세트 썸네일, 필터, 같은 외형·색상 변형, 아이템 출처 | 이름을 모르는 의상 탐색 |
| Guild Wars 2 Fashion Templates | 의상과 염색 조합의 템플릿 저장·공유 | 코디 전체를 하나의 단위로 관리 |
| Anamnesis | 외형·장비 파일 저장 및 선택한 부분만 불러오기 | 캐릭터 외형과 코디 분리 |
| XIV Dye Tools | 색상 매칭과 배색 도구 | 염색 기능의 후속 확장 |

### 2.1 마비노기 캐릭터 시뮬레이터

출처: https://mabi.sigkill.kr/charsimulator/

**확인 내용**

- 캐릭터 외형과 부위별 아이템을 변경하고 염색할 수 있다.
- 자주 쓰는 아이템을 보관하고 이미지·GIF·캐릭터를 저장할 수 있다.
- 캐릭터 조회는 마비노기 온라인 공식 홈페이지의 로그아웃 외형 정보를 이용한다.
- 게임과 외형·색상이 다르거나 일부 의상이 비정상적으로 표시될 수 있음을 안내한다.

**적용 제안**

- 부위 선택에서 의상 교체·염색으로 이어지는 흐름을 기본으로 삼는다.
- 편집한 코디를 보관하고 이미지로 남길 수 있게 한다.
- 마비노기 모바일의 캐릭터명 조회는 데이터 공급 경로가 확인되기 전까지 전제하지 않는다.

### 2.2 Prilus Mabi Tool

출처: https://prilus.gitlab.io/ko/charsimul

**확인 내용**

- 의상을 그림 목록과 검색으로 찾고 외형·염색을 편집한다.
- 색상 코드 입력·복사, 색상 즐겨찾기, 일부 또는 전체 기본색 복원, 변경 되돌리기를 지원한다.
- 캐릭터 상태를 저장하고 코드·링크로 공유하며 이미지·GIF를 출력한다.

**적용 제안**

- 가장 직접적인 사용성 기준으로 삼는다.
- 의상 탐색과 색상 재사용, 부분 초기화, 실행 취소를 우선 반영한다.
- 다중 캐릭터·모션·필드 배치는 기본 코디 편집이 완성된 뒤 검토한다.

### 2.3 Wowhead Transmog

출처: https://www.wowhead.com/ptr/transmog

**확인 내용**

- 세트를 텍스트뿐 아니라 이미지 썸네일로 탐색한다.
- 필터와 동일 외형·색상 변형의 연결, 아이템 출처 정보를 제공한다.

**적용 제안**

- 이름을 모르는 사용자를 위해 썸네일 탐색을 제공한다.
- 데이터로 확인되는 세트는 구성품을 함께 보여준다.
- 동일 외형 묶기는 모델·염색 가능 부위 차이를 확인한 뒤 적용한다.

### 2.4 Guild Wars 2 Fashion Templates

출처: https://help.guildwars2.com/hc/en-us/articles/48794217062931-Feature-Explanation-Fashion-Templates

**확인 내용**

- 스킨과 염색 조합을 템플릿으로 저장·공유하고 다시 적용한다.

**적용 제안**

- 의상 하나의 즐겨찾기와 완성된 코디 전체의 저장을 구분한다.
- 사용자 기본 외형을 유지하면서 코디만 교체할 수 있게 한다.
- GW2의 적용 비용·계정 보유 조건은 참고 기능에 포함하지 않는다.

### 2.5 Anamnesis

출처: https://github.com/imchillin/Anamnesis/wiki/Loading-and-Saving-Character-Files

**확인 내용**

- 외형과 장비를 캐릭터 파일로 저장한다.
- 파일을 불러올 때 외형·의상·액세서리·무기 등 일부만 선택할 수 있다.

**적용 제안**

- 캐릭터 외형과 코디를 분리하고 전체 상태 저장도 제공한다.
- 다른 사람의 코디에서 옷만 불러올 수 있게 한다.
- 참고 대상은 파일 관리와 부분 적용 UX다. 게임 프로세스를 수정하는 방식을 채택한다는 의미는 아니다.

### 2.6 XIV Dye Tools

출처:
- https://xivdyetools.app/
- https://developers.xivdyetools.app/

**확인 내용**

- 원하는 색과 가까운 게임 염료를 찾는 기능과 배색 관련 도구를 제공한다.

**적용 제안**

- 초기에는 최근 색·즐겨찾기·색상 코드 공유를 우선한다.
- 이후 팔레트와 배색 추천을 검토한다.
- 모바일의 사용 가능한 색상 집합과 선택 규칙이 확인돼야 실제 적용 가능한 색 추천을 제공할 수 있다.

## 3. MobiAtelier의 사용 목적

제안하는 중심 흐름은 다음과 같다.

1. 내 캐릭터와 비슷한 외형을 한 번 설정하고 저장한다.
2. 부위별 목록에서 의상을 찾아 입힌다.
3. 염색을 시도하고 후보를 비교한다.
4. 코디와 이미지를 저장한다.
5. 의상명·색상 코드를 보고 게임에서 직접 적용한다.

초기에는 외형을 수동으로 맞춘다. 캐릭터명 자동 조회나 계정 정보 연동은 구현 가능성을 확인한 별도 기능으로 다룬다.

## 4. 저장 단위 제안

| 저장 단위 | 내용 | 사용 예 |
|---|---|---|
| 캐릭터 외형 | 성별·체형·얼굴·피부·헤어·눈 등 지원하는 외형 항목 | 내 기본 외형 |
| 코디 | 부위별 의상·액세서리·염색값 | 평상복, 겨울 코디 |
| 전체 작업 | 외형·코디·카메라·배경 설정 | 작업하던 상태 이어하기 |

- 코디를 불러올 때 현재 외형을 유지하는 선택을 제공한다.
- 전체 캐릭터 상태를 불러오는 선택도 제공한다.
- 공유 파일에는 리소스 대신 ID·설정값·색상값을 기록한다.
- 파일 포맷 버전과 작성 당시 게임 버전을 기록하는 방안을 검토한다.
- 버전 차이로 찾을 수 없는 항목은 안내하고, 가능한 부분은 복원한다.

## 5. 의상 탐색 제안

### 5.1 기본 구성

- 부위 선택
- 이름 검색
- 의상 썸네일과 표시 이름
- 즐겨찾기와 최근 사용
- 현재 외형에서 착용 가능한 항목 필터
- 확인된 세트의 구성품 표시와 세트 입히기

게임 아이콘을 우선 활용하고, 실제 착용 모습의 자동 썸네일 생성은 비용과 로딩 시간을 측정한 뒤 검토한다. 이름이 불분명한 항목은 내부 ID도 확인할 수 있게 한다.

### 5.2 항목 상태

| 상태 | 제안하는 처리 |
|---|---|
| 일반 착용 가능 항목 | 기본 목록에 표시 |
| 성별·체형 제한으로 착용 불가 | 숨김 또는 비활성 표시, 이유 제공 |
| 개발용·숨김·용도 불명 | 고급 옵션에서만 표시 |
| 현재 획득·판매 여부 미확인 | 판매 중이라는 표현 없이 표시 |
| 리소스 누락·로딩 실패 | 해당 항목 오류 안내, 기존 코디 유지 |

설치 데이터에 존재한다는 사실을 현재 구매하거나 획득할 수 있다는 의미로 사용하지 않는다. 최신순·획득처·판매 상태 필터는 근거 데이터가 있는 범위에서만 제공한다.

## 6. 염색 편집 제안

| 기능 | 동작 |
|---|---|
| 염색 부위 선택 | 바뀌는 영역을 잠시 강조 |
| 색상 입력 | 색상 선택창과 HEX·RGB 입력 |
| 색 복사·붙여넣기 | 다른 의상·슬롯에 같은 값 적용 |
| 최근 색·즐겨찾기 | 자주 쓰는 색 재사용 |
| 기본색 복원 | 선택 부위 또는 의상 전체 복원 |
| 실행 취소·다시 실행 | 의상·색상 변경을 되돌리거나 재적용 |

- 부위 이름이 확인되지 않으면 억지로 명명하지 않고 부위 번호와 강조 표시를 사용한다.
- 색상 판단 중에는 강조 효과가 결과색을 가리지 않게 한다.
- 의상마다 실제 연결된 슬롯만 편집 가능하게 한다.
- 편집 중 화면에 표시된 색과 저장·재로딩한 색이 일치하는지 검증한다.
- 자유 색상 시험과 게임에서 실제 선택 가능한 색상의 구분이 필요할 수 있다. 실제 제약은 데이터 확인 후 결정한다.
- 팔레트 저장은 후속 기능으로 둔다. 의상마다 슬롯 의미가 다르므로 다른 옷에 적용할 때 대상 슬롯을 고르게 한다.
- 피부·헤어·각 재질의 색 재현 정확도는 렌더링 검증 과제로 별도 관리한다.

## 7. 후보 비교와 카메라 제안

원래 목적에 맞춰 추가로 제안하는 기능이다. 아래 기능이 모든 레퍼런스에 공통으로 있다는 의미는 아니다.

- 현재 코디를 A로 보관하고 다른 조합을 B로 보관한다.
- 같은 카메라·조명에서 A/B를 빠르게 전환한다.
- 첫 구현은 캐릭터 두 명의 동시 렌더링 없이 상태 전환으로 만든다.
- 마음에 드는 부위를 잠그고 다른 부위만 교체할 수 있게 한다.
- 정면·측면·후면·전신·얼굴 보기 버튼을 제공한다.
- 외형 편집은 얼굴, 의상 편집은 전신으로 이동할 수 있게 한다.
- 카메라 자동 이동을 원하지 않는 사용자를 위해 수동 시점 유지도 검토한다.
- 배경·조명 프리셋을 바꿔도 코디 비교 조건을 동일하게 유지한다.

## 8. 저장·공유 결과물 제안

| 결과물 | 목적 |
|---|---|
| 코디 파일 | 다시 편집하거나 다른 사용자에게 전달 |
| PNG 이미지 | 디스코드 등에서 모습 공유 |
| 코디 정보 카드 | 이미지·의상명·부위별 색상 코드를 함께 전달 |

코디 정보 카드는 게임에서 실제로 따라 할 때의 기록이다. 받는 사람도 게임 설치본과 해당 항목을 읽을 수 있는 버전이 필요하다.

단순 PNG 저장을 먼저 만들고 정보 카드는 후속으로 확장한다. 계정·온라인 갤러리·공유 서버는 초기 요구에 넣지 않는다.

## 9. 화면 구성 제안

| 영역 | 내용 |
|---|---|
| 왼쪽 | 외형·의상 탭, 부위, 검색, 썸네일, 즐겨찾기·최근 사용 |
| 중앙 | 캐릭터, 카메라, 배경·조명, A/B 비교 |
| 오른쪽 | 현재 착용 목록, 선택 항목 상세, 염색 |
| 공통 동작 | 저장·불러오기·내보내기, 실행 취소·다시 실행 |

- 설치 경로 선택은 첫 실행과 설정 화면에 둔다.
- 처음에는 기본 프리셋과 새 캐릭터·저장한 외형 불러오기를 제공한다.
- 색상 창이나 목록이 캐릭터를 지나치게 가리지 않도록 한다.
- 파츠 교체 중 진행 상태를 표시하고 실패하면 이전 상태를 유지한다.

## 10. 개발 우선순위 제안

현재 기술 시험 결과와 제품 기능의 완성 여부를 구분한다. 언팩 저장소에서 성공한 단일 조합을 전체 의상 지원 완료로 취급하지 않는다.

| 단계 | 목표 | 완료 기준 예시 |
|---|---|---|
| 기술 기반 | 설치 경로 선택, 시트 이름·기본색 조회, 얼굴 파츠, 의상 교체·해제 | 설치본에서 대표 조합을 불러오고 반복 교체 시 메모리 누적을 확인 |
| 첫 실사용 버전 | 기본 외형 저장, 썸네일 검색, 의상·염색, 실행 취소, 코디 저장·불러오기, PNG | 설정한 외형을 재사용하며 옷·색을 바꾸고 재실행 후 복원 |
| 사용성 개선 | 즐겨찾기, 최근 사용, 부위 잠금, A/B, 팔레트, 정보 카드 | 같은 외형에서 후보를 비교하고 필요한 코디 정보를 전달 |
| 이후 확장 | 포즈·표정·애니메이션, 다중 캐릭터, 배경·촬영 | 기본 편집의 안정성과 리소스 지원 범위 확보 후 결정 |

### 첫 버전에서 미루는 기능

- 캐릭터명 자동 조회와 계정 연동
- 온라인 코디 갤러리와 로그인
- 실시간 시세·획득 비용 계산
- 다중 캐릭터·필드 배치·GIF
- 자유 포즈 편집
- 제약을 무시하는 다른 성별·개발용 모델 조합

## 11. 후속 결정·검증 사항

- 외형 설정 항목과 성별·나이·키·체형의 실제 지원 범위
- 의상 슬롯 체계와 세트·겹침·숨김 규칙
- 염색 슬롯 표시명 및 게임에서 가능한 색상 범위
- 기본색 출처와 피부·헤어 색 적용 방식
- 외형을 유지하고 코디만 불러올 때 헤어·모자 등의 충돌 처리
- 숨김·미사용 데이터를 기본 목록에서 제외하는 기준
- 썸네일 출처와 실제 착용 미리보기 생성 방식
- 저장 파일 형식과 누락 항목 복구 정책
- 일반 보기·색상 비교에 사용할 조명 프리셋
- 최초 로딩·의상 교체 시간·메모리의 측정 기준

## 12. 제안 요약

우선순위는 **내 외형 재사용 → 의상 탐색 → 부위별 염색 → 후보 비교 → 코디 기록**으로 둔다.

가장 직접적인 UX 기준은 마비노기 시뮬레이터와 Prilus다. Wowhead에서는 이미지 탐색, GW2에서는 코디 템플릿, Anamnesis에서는 부분 불러오기, XIV Dye Tools에서는 색상 재사용과 배색 확장 방향을 참고한다.

이 문서는 레퍼런스 조사와 기획 제안이다. 확정된 범위는 이후 별도 기획 문서와 구현 작업에 반영한다.
