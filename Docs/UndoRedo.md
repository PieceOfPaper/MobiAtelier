# 실행 취소·다시 실행 기획

> 정리일: 2026-11-01
> 확정 사항·제안·미정 표기를 유지한다. 구현 완료를 의미하지 않는다.
> 화면·상태 전환은 [프로그램 플로우](ProgramFlow.md)를 참고한다.

## 실행 취소·다시 실행

**확정**
- Ctrl+Z: 실행 취소. Ctrl+Y: 다시 실행.
- 꾸미기 창의 공통 작업 영역에 같은 동작의 버튼을 제공한다. 실행할 이력이 없으면 비활성 표시한다.
- 앱 실행 후 사용자가 변경한 장면 상태를 기준으로 이력을 쌓는다. 외형·의상·염색과 사용자가 조작한 카메라 상태를 대상으로 한다.
- 시작 시 마지막 작업을 복원하거나 최초 캐릭터를 배치한 결과를 기준 상태로 삼고, 그 이후 편집부터 기록한다.
- 이력은 현재 실행 중에만 유지한다. 이전 실행의 이력을 자동 저장이나 코디 JSON에서 복원하지 않는다.
- JSON 불러오기 또는 전체 초기화가 성공하면 실행 취소·다시 실행 이력을 모두 비운다. 새 상태를 기준으로 이후 편집부터 다시 기록한다.
- JSON 불러오기와 전체 초기화 자체는 되돌릴 수 있는 편집으로 기록하지 않는다. 이 동작 뒤 Ctrl+Z로 이전 코디에 돌아가지 않는다.
- 불러오기·초기화가 취소되거나 실패하면 현재 작업과 이력을 유지한다. 준비 단계에서 이력을 먼저 지우지 않는다.
- 일반 자동 저장·수동 JSON 저장은 이력을 지우지 않는다.
- 패널 이동·크기 변경·폴드아웃 펼침 같은 UI·환경 설정은 장면 편집 이력에서 제외한다.

**이력 처리 제안**
- 외형 변경과 그에 따른 의상 표시 재평가는 한 작업으로 복원한다.
- 의상 교체와 기본 염색 초기화도 한 작업이다. 취소하면 이전 의상과 그 사용자 염색값이 함께 돌아온다.
- 컬러피커 연속 드래그는 한 번의 편집 묶음으로 처리하고 색 코드 입력은 확정 시 기록한다.
- 취소한 뒤 새 편집을 하면 다시 실행 분기는 비운다.
- 카메라 연속 드래그·연속 휠 조작은 편집 묶음으로 기록한다. 매 프레임을 별도 이력으로 만들거나 UI에 따른 자동 뷰포트 보정을 사용자 편집으로 기록하지 않는다.
- 텍스트 입력에 포커스가 있으면 해당 입력란의 편집 취소와 전역 코디 실행 취소가 동시에 실행되지 않게 한다.

## 남은 결정

- 연속 편집의 묶음 기준·텍스트 포커스 처리·메모리 관리의 세부 구현. 임의의 고정 이력 개수로 이번 실행의 편집을 잘라내는 정책은 확정하지 않았다.

## 검수 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| Ctrl+Z·Ctrl+Y 및 버튼 | 같은 실행 취소·다시 실행 동작 |
| 앱 실행 후 외형·의상·염색·카메라 변경 | 시작 기준 상태까지 실행 취소 가능 |
| 앱 재실행 | 마지막 장면은 복원하지만 실행 취소·다시 실행 이력은 비어 있음 |
| JSON 불러오기 성공 | 두 이력 모두 삭제, 이후 편집부터 새로 기록 |
| 전체 초기화 성공 | 두 이력 모두 삭제, 초기화 자체는 실행 취소 불가 |
| 불러오기·초기화 취소 또는 실패 | 기존 작업·이력 유지 |
| JSON 저장·자동 저장 | 이력 유지 |
