# 마지막으로 접속한 캐릭터 불러오기

> 정리일: 2026-11-12
> 사용자 결정(2026-11-12)을 기준으로 한다. 확정·제안·미정 표기를 유지한다.
> 목적: 점검 중처럼 게임에 접속할 수 없을 때도 내 캐릭터를 아틀리에에서 바로 열어 본다.

## 1. 진입과 흐름

**확정**
- 시스템 메뉴 세 번째 항목 "마지막으로 접속한 캐릭터 불러오기"(가져오기 다음, 초기화 앞).
- 성공하면 작업을 교체하고 꾸미기 이력을 비운다. 가져오기와 같은 준비·조립·교체 경로를 쓴다. 배경은 현재 선택을 유지하고 카메라는 기본 구도로 맞춘다.
- 불러오지 못한 부위는 장착하지 않는다. 오류 팝업에 어떤 부위를 왜 못 불러왔는지 보여 준다. 승인을 따로 묻지 않는다.

**구현 선택 [제안]**
- 작업을 바꾸고 이력을 비우므로 실행 전에 확인 팝업(취소·불러오기)을 띄운다. 취소·X·ESC는 메뉴로 돌아간다.
- 모두 불러오면 팝업 대신 상단 안내를 띄운다. 지원하지 않는 항목과 근사 색은 안내·팝업 아래에 함께 적는다.

| 상황 | 결과 |
|---|---|
| 캐시 파일 없음 | "게임에서 캐릭터로 한 번 접속한 뒤 다시 시도" 안내, 현재 작업 유지 |
| 형식 해석 실패 | 게임 업데이트 가능성 안내, 현재 작업 유지 |
| 조립 실패 | 현재 작업 유지 |
| 일부 부위 실패 | 나머지를 불러오고 실패 부위 목록 팝업 |

## 2. 읽는 파일

**확정 (AGENTS.md 10장 예외)**
- `%USERPROFILE%\AppData\LocalLow\devCAT\마비노기 모바일\TitleDisplay.bin` 하나만 사용자가 실행할 때 읽기 전용으로 읽는다. 게임이 타이틀 화면에 세울 캐릭터 외형을 저장해 둔 캐시다.
- PlayerPrefs·쿠키·친구·초상화 캐시는 읽지 않는다. 캐릭터 ID는 읽지도 저장하지도 않는다.
- 다른 캐릭터를 불러오려면 게임에서 그 캐릭터로 접속했다 종료해야 한다 [추정: 마지막 접속 캐릭터로 덮어씀].
- 형식은 SJON이며 기존 `Sjon.Decode`로 읽는다. 필드 이름이 스키마에 함께 저장돼 필드 순서 변경에는 강하다.

## 3. 대응 표

캐시의 `DisplayData`(ActorDisplayData) [확인: 실제 파일]:

| 캐시 | 형태 | 아틀리에 |
|---|---|---|
| Gender·Age·HeightModifier | 값 | 그대로 |
| BodyType·HeadType·HairType | [번호, 시트 ID] | 시트 ID 그대로 |
| SkinColor | RGBA | 가장 가까운 피부색 행 |
| BodyParts | 모델 이름 + 염색 | 헤어(색: 7 Hair, 17 Hair1 → 가장 가까운 헤어 색 행), 눈(색: 8 Eye → 눈 색 행), 입, 수염, 얼굴꾸밈, 몸꾸밈을 시트에서 거꾸로 찾는다. 머리 모델은 HeadType으로 이미 정해진다 |
| Clothes·Accessories | 모델 이름 + 염색 0~5 | 패션장비 거꾸로 찾기, 염색 Slot0~5(시트 기본색과 같으면 기록하지 않음) |
| Tools[-1] | 무기 모델 | 의상 › 무기. IsWeaponHidden이면 장착하지 않음 |
| CombatJobAnimationCondition | 직업 ID | 무기 자세 직업. 자세는 넣음 |
| 그 밖 | — | 4장 |

- 염색 번호는 게임 DyeSlot 열거형이다: 0~5 Slot0~5, 6 Skin, 7 Hair, 8 Eye, 9 Eyebrow, 10 Mouth, 13 Beard, 14 FaceTattoo, 15 BodyTattoo, 17 Hair1, 18 HairAccessory.
- 도구 번호: -1 무기, 1~8 생활 도구, 9 악기, 10 연금 도구 [확인: 실제 파일과 ToolIndex 이름 순서].
- 입 색은 다루지 않는다(기본 프리셋 값).

### 의상 후보 결정 (역방향 조회)

설치본 기준 모델 3,709개 중 716개를 여러 패션장비 행이 함께 쓴다 [확인]. 다음 순서로 하나를 고른다.

1. 지금 캐릭터의 성별·나이 열(남·여·소년·소녀, 모델 변형 포함)에 그 모델이 있는 행
2. 착용 가능 성별이 맞는 행
3. 공개 행. 일반 빌드는 공개 행만 후보이며, 숨김 행뿐이면 "숨김 항목"으로 실패 처리한다
4. 이름이 있고 `<`로 시작하지 않는 행(`<사용하지 않음>` 등)
5. 시트 기본 염색이 캐시 색에 가장 가까운 행
6. 시트 순서

- 여러 모델로 된 의상(검+방패 등)은 모든 모델을 가진 행만 후보로 본다.
- 같은 부위에 두 의상이 나오면 앞의 것만 장착하고 뒤의 것은 실패로 알린다.
- 꾸밈 시트에서 같은 모델을 쓰는 행이 여럿이면 공개 행을 먼저 고른다.

### 색

- 피부·헤어·눈 색은 시트 색 중 RGB 거리가 가장 가까운 행을 고른다. 일반 빌드는 꾸미기 숨김 색을 제외한다. 정확히 같지 않으면 "가장 가까운 색으로 고른 항목"에 적는다.
- 헤어 색은 Hair와 Hair1의 거리 합으로 고른다(한 가지 색 행은 두 영역 모두 첫 색과 비교).

아직 아틀리에에 기능이 없어 불러오지 않는다. 안내에 이름만 적는다. 목록과 계획은 [미구현·생략 목록](ImplementationGaps.md)이 기준이다.

| 캐시 | 안내 이름 |

## 5. 검증

- [확인] Windows 빌드를 별도 데이터 폴더로 실행해 실제 캐시를 불러왔다. 외형·의상 6부위·무기·염색·꾸밈이 들어오고 지원하지 않는 항목 5개가 안내됐다. 피부·헤어·눈 색은 시트 색과 정확히 일치했다.
- [확인] 신발 모델 이름만 없는 이름으로 바꾼 캐시 복사본(`-maTitleDisplay`)으로 실패 팝업과 신발 미장착을 확인했다.
- [미확인] 남성·어린 캐릭터, 로브·후드 착용, 숨김 의상을 입은 캐릭터.
- 시험 옵션: `-maDataDir <폴더> -maScreenshot <png> -maShotLastCharacter [-maTitleDisplay <파일>] [-maShotUI dismiss]`.
