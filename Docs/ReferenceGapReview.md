# 레퍼런스 대비 차이와 기획 보강안

> 정리일·공개 자료 재확인일: 2026-11-02
> 비교 기준: main `2e409c4`의 항목별 기획서. 구현 완료 여부와 구분한다.
> 기존 확정 사항은 유지한다. 아래 신규 기능은 모두 **제안**이며 합의 전 필수 구현 범위로 확대하지 않는다.
> 같은 날 후속 결정: UI 숨김·렌즈 화각은 채택했다. 카메라 쳐다보기·행동은 구현 가능성 검증 후 도입한다. 배경은 별도 에이전트 작업 뒤 재검토한다. 무기 표시·촬영 구도·비율은 보류다. 최신 범위는 PhotoMode.md·Camera.md·StudioFeatureReview.md가 우선한다. 아래의 시점 버튼은 렌즈 화각과 별개의 제안이다.

## 1. 비교 결과

기본 외형·의상·염색 편집 범위는 이미 기획되어 있다. 레퍼런스와의 주요 차이는 후보를 다시 찾고, 비교하고, 기록하는 편의 기능이다. 설치본을 직접 읽는 Windows 도구라는 배포 방식의 차이를 기능 부족으로 취급하지 않는다.

공개 도움말·공식 문서로 기능 존재를 확인했다. 서비스를 직접 조작하거나 렌더링·성능·모든 데이터 연결을 시험하지 않았다. 자료가 공개하는 기능만 비교하며 각 레퍼런스가 표의 모든 기능을 지원한다는 뜻은 아니다.

## 2. 유지할 제품 방향

- 단일 이동·리사이즈 꾸미기 창, 폴드아웃·검색 드롭다운을 유지한다. 3분할 고정 배치·썸네일 격자를 의무화하지 않는다.
- 표기는 `데이터ID - 이름`, 에디터 숨김 항목은 `[숨김] 데이터ID - 이름`이다.
- 숨김 데이터·시트 없는 직접 모델은 `UNITY_EDITOR` 전용이다. 즐겨찾기·이력·공유·추후 기능에도 동일한 공개 판정을 적용한다.
- 구매·해금·직업으로 공개 항목 선택을 잠그지 않는다. 실제 모델 호환은 검사한다.
- 임의 RGB 편집을 유지한다. 색 즐겨찾기·팔레트·영역 강조·부분 기본색 복원을 필수나 추가 결정 대기로 되살리지 않는다.
- 새 의상을 고르면 해당 의상의 초기색을 사용한다. 색 유지 제안을 이 정책에 섞지 않는다.
- 전체 장면 JSON 저장과 JSON 불러오기·초기화 성공 시 undo/redo 이력 삭제를 유지한다.

## 3. 우선 검토할 보강안

다음 순서는 추천이며 개발 일정 확정이 아니다. 현재 꾸미기 UI·외형·의상·염색·저장 구현을 먼저 완성한다.

### 3.1 의상 즐겨찾기·최근 사용 — 우선 제안

**문제**: 이름·ID를 알아도 자주 쓰는 옷을 매번 다시 검색해야 한다.

- 검색 드롭다운 안에 즐겨찾기·최근 사용 묶음을 제공한다. 기존 이름·ID 검색을 그대로 쓴다. 별도 격자 창은 만들지 않는다.
- 즐겨찾기는 사용자가 등록·해제한다. 최근 사용은 실제 적용에 성공한 사용자 선택만 기록한다. 중복 ID는 최신 위치로 이동한다.
- 실패·취소·뒤늦게 완료된 무효 로딩 요청은 최근 사용으로 기록하지 않는다. 복원·undo/redo로 목록 순서를 계속 바꾸지 않는 것을 제안한다.
- ID 기반 앱 설정으로 보관한다. 의상의 사용자 염색이나 전체 코디를 함께 저장하는 기능으로 만들지 않는다. 코디 JSON·장면 이력과 구분한다.
- 일반 빌드에서는 저장된 ID의 현재 공개 여부를 재검사한다. 에디터의 숨김 즐겨찾기를 일반 목록에 노출하지 않는다.
- 최근 사용 최대 개수·정렬·삭제된 ID의 안내 방식은 채택 후 결정한다.

**검수 예**: 즐겨찾기한 신발을 재실행 후 다시 찾는다. 새 선택에는 신발 기본색이 적용된다. 실패한 의상은 최근 목록에 추가되지 않는다.

### 3.2 전신·얼굴·정면·후면 보기 — 우선 제안

**문제**: 머리와 의상을 번갈아 편집할 때 수동 줌·회전을 반복한다.

- 전신·얼굴은 프레이밍 버튼, 정면·후면은 방향 버튼으로 구분한다.
- 방향 버튼은 현재 줌·팬을 가능한 한 유지하고, 프레이밍 버튼은 해당 부위가 보이는 거리·팬을 맞추는 것을 제안한다.
- 외형·의상 선택만으로 카메라를 강제로 옮기지 않는다. 사용자가 버튼을 눌렀을 때 이동한다.
- 모델을 돌리거나 체형을 바꾸지 않는다. 현재 키·체형·앱 화면비에서 프레이밍을 계산한다.
- 버튼으로 확정한 카메라 변경은 기존 카메라 편집처럼 JSON·자동 저장·undo/redo에 반영한다. UI 버튼 클릭이 카메라 드래그로 이어지지 않게 한다.
- 작은 화면에서의 여백·카메라 감도·팬 이후 회전 정책은 기존 Camera.md의 조정 과제로 유지한다.

**검수 예**: 얼굴 보기 후 후면 보기에서 머리 뒤를 확인한다. Ctrl+Z로 직전 카메라 상태를 복원한다. 세로 창에서도 얼굴 비율이 왜곡되지 않는다.

### 3.3 최소 PNG 출력·코디 목록 복사 — 우선 제안

**문제**: JSON은 다시 편집할 때 유용하지만 다른 사람에게 결과를 보여주거나 게임에서 따라 하기는 어렵다.

- PNG는 현재 확정된 캐릭터·카메라를 사용하고 편집 UI·팝업을 제외해 저장하는 최소 기능부터 검토한다.
- 별도 촬영 씬·포즈·표정·배경 변경·GIF·고해상도 배율·투명 배경을 자동 포함하지 않는다.
- 모델 교체 중에는 촬영을 잠그거나 준비 완료 뒤 실행한다. 마지막 정상 장면과 요청 중인 이름을 섞어 출력하지 않는다.
- 파일 선택 취소·쓰기 실패는 장면·이력에 영향을 주지 않는다. 저장 경로는 JSON의 최근 폴더와 자동 공유하지 않는다.
- 코디 목록 복사는 별도 제안이다. `부위 / ID - 이름 / 적용 상태 / 파트별 사용자 HEX`를 텍스트로 복사한다. 기본색이 텍스처·원본 재질 조합이면 임의의 대표 HEX로 환산하지 않고 기본색으로 표기한다.
- 미적용·다른 의상에 가림을 구분한다. 설치 경로·계정 정보는 포함하지 않는다. 일반 빌드에서 제한된 항목의 상세를 공유 출력으로 우회 노출하지 않는다.
- 정보 카드 이미지는 이 텍스트 결과가 유용한지 확인한 다음 검토한다.

**검수 예**: 같은 장면의 PNG와 코디 목록에서 의상이 일치한다. 원피스에 가린 하의는 적용 중인 옷으로 오해하지 않게 기록한다.

### 3.4 외형 유지·코디만 불러오기 — 다음 단계 제안

**문제**: 다른 코디 JSON을 열면 얼굴·체형·카메라도 바뀐다.

- 파일 저장은 현재처럼 전체 장면 하나로 유지한다. 불러올 때 기본값은 전체 장면으로 둔다.
- 후속 옵션으로 코디만 적용을 제공한다면 의상·액세서리·무기와 해당 파트 사용자 염색만 적용하고 외형·외형 색·카메라는 유지한다.
- 눈장식처럼 외형 편집과 장비 참조가 겹치는 값은 저장 상태의 실제 소유 필드를 확인해 중복 적용하지 않는다. 정확한 경계는 채택 전 결정한다.
- 대상 슬롯의 명시적 없음은 해제로 적용하고, 필드 자체가 없는 구버전 파일은 형식 마이그레이션 규칙으로 해석한다. 두 경우를 동일하게 취급하지 않는다.
- 현재 외형에 맞지 않는 의상은 기존처럼 선택·염색을 보존하고 미출력·사유를 표시한다. 숨김 제한·누락 ID는 기존 부분 복원 안내를 따른다.
- 이 옵션도 JSON 불러오기이므로 성공하면 기존 undo/redo 이력을 비운다. 실패·취소 시 장면·이력을 유지한다.
- 헤어·얼굴형 등까지 세분화한 체크박스와 저장 형식 여러 종류는 첫 제안에 포함하지 않는다.

**검수 예**: 다른 성별로 저장한 파일에서 옷만 불러와도 현재 얼굴·카메라는 유지된다. 호환 불가 의상은 사유가 표시되고, 성공 뒤 이전 코디로 Ctrl+Z가 되지 않는다.

### 3.5 후보 A/B 비교 — 다음 단계 제안

**문제**: 두 조합을 비교하려고 undo/redo나 파일 불러오기를 반복해야 한다.

- 레퍼런스 공통 기능이 아니라 MobiAtelier의 비교 목적에서 도출한 제안이다.
- 초기에는 A에 보관·B에 보관·A/B 보기만 제공한다. 두 캐릭터 동시 렌더링은 요구하지 않는다.
- 두 후보는 현재 세션의 메모리에서 장면 값으로 보관한다. 카메라·조명은 공통으로 유지해 의상·색만 비교할 수 있게 한다.
- 임시 보기와 편집 확정을 구분한다. 임시 전환으로 현재 작업·자동 저장·이력을 덮어쓰지 않는다. 현재 작업에 적용을 눌렀을 때 하나의 편집으로 기록하는 것을 제안한다.
- 임시 보기 중 편집 허용 여부·종료/JSON 불러오기/초기화 시 후보 정리·미적용 선택 포함 범위는 채택 전 결정한다. 최소안은 보기 중 편집을 막고 기존 작업으로 돌아온 뒤 편집한다.
- 두 후보 모두 현재 공개·호환·리소스 검사를 거친다. 실패하면 현재 정상 장면을 유지한다.

**검수 예**: A/B를 여러 번 전환해도 같은 시점에서 비교되며 저장된 작업이 바뀌지 않는다. B 적용은 Ctrl+Z 한 번으로 되돌린다.

## 4. 이후 검토 또는 유지할 제외 범위

| 항목 | 처리와 이유 |
|---|---|
| 썸네일 탐색 | 이름을 모르는 옷 탐색에는 유용하다. 현재 확정 UI에 강제하지 않고 후속 선택 기능으로 둔다 |
| 세트 입히기 | 원본 시트의 세트 관계·구성품 근거 확인 후 제안한다. 이름 접두사만으로 묶지 않는다 |
| 착용 가능 필터 | 현재 데이터에서 계산 가능한 모델 호환만 검토한다. 직업·구매·해금 제한을 되살리지 않는다. 필터 밖 기존 선택도 유지한다 |
| 포즈·표정·모션·배경·조명 | 촬영모드 후속 범위를 유지한다. 색 재현 검증을 위해 조명 조건을 통제하는 일은 별도 기술 검증이다 |
| 게임 염료 매칭·팔레트·배색 추천 | 자유 RGB 중심의 현재 필수 범위에 추가하지 않는다 |
| 온라인 갤러리·계정 조회·링크 서버 | 기본 편집에 필요하지 않으며 확인된 모바일 데이터 공급 경로도 없다. 도입하지 않는다 |
| 숨김 공개 옵션·다른 성별 강제 모델 | 현재 제한·호환 정책과 충돌한다. 도입하지 않는다 |

## 5. 기능 추가보다 먼저 검증할 것

- 현재 기획 항목이 구현 완료된 것으로 오해하지 않는다. PROGRESS.md 기준 꾸미기 편집 UI는 아직 구현 전이다.
- 얼굴·피부·헤어·의상 재질의 색 재현, 기본색·저장색 왕복, 원피스·모자·어린 외형 조합을 대표 검증 대상으로 둔다.
- 게임 화면과 비교할 때 같은 외형·의상·색과 가능한 한 같은 조명·카메라 조건을 기록한다. 차이의 원인을 색 입력·색 공간·셰이더·조명으로 나눠 확인한다. 게임과 완전히 같다고 보장하지 않는다.
- 연속 선택·빠른 색 편집·반복 의상 교체·재실행 복원을 확인한다. 목표 시간·메모리 수치는 측정 전 임의로 확정하지 않는다.
- 새 기능을 채택하면 해당 항목별 기획서에 확정 사양을 옮기고 필요한 상태 전환만 ProgramFlow.md에 연결한다.
