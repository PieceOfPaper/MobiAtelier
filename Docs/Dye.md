# 염색 편집 기획

> 정리일: 2026-11-02
> 확정 사항·제안·미정 표기를 유지한다. 구현 완료를 의미하지 않는다.
> 화면·상태 전환은 [프로그램 플로우](ProgramFlow.md)를 참고한다.

## 염색

- **확정**: UI에는 현재 대상의 실제 염색 파트만 표시하고, 각 파트를 컬러피커로 편집할 수 있게 한다. 별도의 영역 강조·비교·팔레트 기능을 필수로 추가하지 않는다.
- 표시할 파트는 현재 대상 모델의 DyeInfo와 실제 머티리얼 연결에서 구한다. 의상마다 Slot0~5 여섯 개를 고정 노출하거나 기본색 필드가 null이라는 이유로 파트를 숨기지 않는다.
- 의상 염색에는 해당 의상의 염색 파트를 표시한다.
- **확정 (사용자 결정 2026-11-02)**: 염색은 염색 가능한 의상에 한해, 그 의상의 염색 가능한 파트만 한다. 염색은 파트 견본을 눌러 여는 컬러피커 창에서 하고, 그 창에서 색 코드도 입력한다.
- **확정 (사용자 결정 2026-11-02)**: 피부·헤어·눈 색은 컬러피커가 아니라 게임 색 시트에서 근거가 있는 색을 고른다. 상세는 [외형 기획](Appearance.md)의 "외형 색".
- 파트 이름이 없으면 파트 1·파트 2처럼 번호로 표시한다. 의미를 추측해 천·단추 등의 이름을 붙이지 않는다. DyeInfo 슬롯의 재질 값(Cloth·Leather·Metal·Wood)은 데이터이므로 천·가죽·금속·나무로 함께 보인다.

### 염색 가능 판정 (2026-11-02 조사·구현)

- Costume.DyePolicy는 Default·AlwaysCantDye 두 값이다. 현재 Costume 1,679행은 모두 Default다 [확인]. AlwaysCantDye면 염색할 수 없는 의상으로 표시한다.
- 실제 염색 가능 여부는 모델 DyeInfo로 정한다. Slot0~5 중 연결(Wiring)이 하나 이상 있는 슬롯이 염색 파트다. 연결이 비어 있는 슬롯(예: 초보자 신발 Slot2, 일부 헤어 Slot0)은 파트로 보이지 않는다 [확인: ModelParts 모델 정의 1,494개의 Slot0~5 슬롯 중 연결 없는 슬롯 24개].
- 염색 파트가 없는 의상(예: 무기 일부 MainTool 9개, 슬롯 0개)은 "염색 파트가 없습니다"로 표시한다.
- 파트는 표시 중(적용)인 의상에만 보인다. 가려졌거나 적용되지 않은 의상은 파트를 표시하지 않고 저장된 염색값만 유지한다.
- 한 의상이 모델 여러 개로 나뉘어 같은 슬롯을 가지면 한 파트로 묶어 함께 바꾼다.

### 컬러피커 창 (2026-11-02 구현)

- 색상 막대 + 채도·명도 사각형, 이전 색·새 색 견본, #RRGGBB 입력. 두 입력은 서로 맞춘다. # 없이 6자리를 넣어도 받는다.
- 고르는 동안은 미리보기만 한다(머티리얼 값만 바꿈). [적용]으로 장면 상태에 넣고 자동 저장 대상이 된다. [취소]·ESC는 원래 색으로 돌린다. 사용자 색이 있는 파트는 [기본색]으로 지울 수 있다(필수 범위 밖이지만 되돌릴 방법이 없어 넣었다).
- 창은 모달이 아니다. 열어 둔 채 카메라를 돌려 볼 수 있다. 다른 편집(드롭다운 선택, 다른 파트 견본, 꾸미기 창 이동)을 시작하면 지금 색으로 적용하고 닫는다 [구현 선택].
- 넓은 앱 창에서는 꾸미기 창 왼쪽, 세로로 긴 앱 창에서는 꾸미기 창 위에 띄운다. 제목을 끌어 옮길 수 있다.
- 색만 바뀌는 편집은 캐릭터를 다시 조립하지 않는다.
- 같은 의상 안의 한 파트가 여러 메시·머티리얼에 연결되면 함께 편집한다. 다른 의상의 같은 슬롯 번호는 별도 대상이다.
- **확정**: 컬러피커와 HEX 코드 입력을 모두 제공한다. 예: #FF00FF.
- **확정**: 의상 염색은 사용자가 임의의 RGB 색을 자유롭게 지정할 수 있다. 게임의 팔레트·색상 해금·선택 가능 색 목록을 제한 조건으로 적용하지 않는다. (피부·헤어·눈 색은 2026-11-02 사용자 결정으로 색 시트 선택으로 바뀌었다.)
- 게임 시트의 CanChangeColor·고정색 설정은 원본 동작과 기본값을 파악하는 참고 정보다. 이를 도구의 색상 선택 잠금으로 사용하지 않는다. 실제 반영을 위한 셰이더·머티리얼 연결이 부족하면 보완 대상으로 기록한다.
- 두 입력은 같은 값을 편집하며 서로 동기화한다. 일반 색 코드 입력은 #RRGGBB를 기준으로 하고 알파 편집 필요 여부는 별도 검토한다.
- 입력 중인 불완전한 코드·잘못된 값은 기존 색을 덮어쓰지 않고 오류를 안내한다.
- 별도 RGB 숫자 입력은 필수 범위에 포함하지 않는다.
- **확정**: 다른 의상을 선택하면 새 의상의 원본 초기색으로 세팅한다. 원본 머티리얼·텍스처를 초기 상태로 읽은 뒤, Costume.DyeColor0~5 중 null이 아닌 기본값만 모델 DyeInfo 연결에 따라 적용한다.
- 시트의 null은 별도 기본 염색값 미지정이다. 초기색이 없다는 의미로 해석하거나 검정·흰색으로 대체하지 않는다. 해당 연결의 원본 머티리얼 값을 유지한다.
- 초기색은 하나의 대표 HEX 값이 아니라 텍스처·재질·여러 염색 영역의 조합일 수 있다. 원본 초기 상태와 사용자 지정 색을 구분해 보관한다.
- JSON·자동 저장·실행 취소에서 복원할 때는 초기 상태를 준비한 뒤 저장된 사용자 색을 덮어쓴다. 복원 중 의상 교체 로직이 사용자 색을 기본값으로 지우면 안 된다.
- 자유로운 색 선택과 염색 영역 생성은 별개다. 실제 색상 반영 지점은 DyeInfo·셰이더·머티리얼로 연결하며, 연결이 없는 영역의 지원은 별도 구현·검증한다.
- 의상별 슬롯 수·존재 여부를 확인한다. 슬롯 번호가 같다는 이유로 이전 옷의 색을 자동 복사하지 않는다.
- 부분 기본색 복원·변경 부위 강조는 필수 범위에 포함하지 않는다. 추가 기획 결정을 기다리는 항목으로 두지 않는다.
- 피부·헤어 색이 여러 UI 영역에 중복 노출될 경우 같은 상태를 편집하도록 한다.
- 즐겨찾기·A/B·팔레트 등은 이 문서의 필수 흐름에 자동 추가하지 않는다.

## 구현에서 확인할 사항

- 색상 직렬화와 원본 알파 보존을 구현에서 정리한다. RGB 입력과 기존 HEX 보조 입력은 유지하며 알파 편집 UI는 필수 범위에 넣지 않는다.
- 피부·헤어·재질별 색상 반영 연결과 재현 범위. 게임의 팔레트 제한 재현은 요구하지 않는다.

## 검수 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| 다른 옷 선택 | 새 옷의 기본 염색 적용 |
| 의상별 염색 UI | 실제 연결된 파트만 표시하고 각 파트를 컬러피커로 편집 가능 |
| 상의와 하의에 같은 Slot0 존재 | 상의 파트 편집이 하의 색상에 전파되지 않음 |
| 컬러피커·HEX 입력 | 같은 색으로 동기화, 잘못된 코드는 미적용 |
| 게임 팔레트에 없는 #FF00FF 입력 | 유효한 RGB 값으로 수용하고 선택한 대상에 반영 |
| 시트 기본 염색값이 null인 의상 | 원본 머티리얼·텍스처 초기 상태 유지 |
| 사용자 색이 저장된 JSON 복원 | 기본 초기화 후 저장된 사용자 색 복원 |
