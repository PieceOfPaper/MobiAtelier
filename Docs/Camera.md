# 카메라 조작 기획

> 정리일: 2026-11-03
> 확정 사항·제안·미정 표기를 유지한다. 구현 완료를 의미하지 않는다.
> 화면·상태 전환은 [프로그램 플로우](ProgramFlow.md)를 참고한다.

## 카메라 조작

## 기준과 근거

2026-11-01 사용자가 직접 설명한 마비노기 모바일의 조작을 기준으로 확정한다. 마우스 좌버튼은 원본 게임의 캐릭터 이동 기능 대신 이 프로그램에서 우버튼과 같은 카메라 회전에 사용한다.

| 입력 | MobiAtelier 동작 | 상태 |
|---|---|---|
| 우버튼만 누르고 드래그 | 캐릭터 기준점을 중심으로 카메라 회전 | 확정 |
| 좌버튼만 누르고 드래그 | 우버튼과 같은 카메라 회전, 캐릭터 이동 없음 | 확정 |
| 좌+우버튼을 누르고 드래그 | 카메라 화면의 좌우·상하 방향으로 평행 이동 | 확정 |
| 마우스 스크롤 | 카메라 확대·축소 | 입력 확정, 방향·감도·범위 조정 |
| 회전 감도·반전·상하 제한 | 게임 느낌을 참고해 조정 | 미정 |

좌+우 이동은 월드 XY에 고정하는 의미가 아니다. 카메라가 Z방향을 보는 예에서는 XY 이동이며, 일반적으로 현재 카메라의 right/up 방향을 사용한다. 드래그로 카메라 전후 이동이나 캐릭터 이동을 하지 않는다.

## 회전 중심과 평행 이동의 관계

**확정**
- 회전 기준은 캐릭터다. 기준점의 몸 기준 높이는 구현 중 조정한다.
- 좌+우 드래그로 구도를 옮겨도 회전 기준점을 이동된 화면 중심이나 임의의 팬 위치로 바꾸지 않는다.
- 이후 좌 또는 우 단독 드래그로 회전하면 다시 캐릭터 기준점 주위의 회전으로 처리한다.
- 회전할 때 캐릭터 모델 자체를 돌리거나 움직이는 방식으로 대체하지 않는다.

**필수 동작 예**
1. 캐릭터를 보고 우버튼 드래그로 회전한다.
2. 좌+우 드래그로 카메라를 옆·위로 옮겨 구도를 바꾼다.
3. 좌 또는 우 단독 드래그로 다시 회전한다.
4. 회전 중심은 여전히 캐릭터다. 2단계의 이동 위치를 새 회전 중심으로 쓰면 안 된다.

**남은 조정**
- 팬 이후 회전 시작 시 팬 오프셋을 어떻게 유지·해제·보간할지는 게임 실동작과 비교해 결정한다. 캐릭터를 화면 중앙으로 즉시 스냅하는 동작은 이번 요구에서 확정하지 않았다.
- 팬·회전 감도, 카메라 충돌·상하각·이동 범위, 확대·축소는 별도 조정한다.
- 0.5x·1x·3x는 아래 화각 프리셋으로 채택한다(사용자 결정 2026-11-02).

## 화각 프리셋

**확정 (사용자 결정 2026-11-02)**
- 0.5x·1x·3x 버튼을 제공한다. 각각 광각·기본·망원 화각으로 사용한다.
- 휠의 거리 확대·축소와 별도로 렌즈 화각을 바꾼다. 전신·얼굴 프레이밍 버튼으로 대체하지 않는다.
- 렌즈 변경은 카메라 거리·회전·팬·캐릭터 외형을 유지한다. 원하는 크기는 거리 줌과 함께 조절한다.
- 렌즈 선택은 카메라 장면 상태로 자동 저장·JSON 복원 대상이다. 2026-11-03 결정으로 회전·팬·거리·화각은 꾸미기 실행 취소 이력에서 제외한다.
- 카메라 초기화는 기본 렌즈 1x로 돌아간다. 렌즈 값이 없는 이전 저장 파일도 1x로 해석한다.
- 앱 창의 자유로운 화면비 정책은 유지한다. 이미지 저장용 비율 선택·촬영 프레임은 보류한다.

**구현값 (게임과 비교 후 조정 가능)**
- 기존 앱의 수직 FOV 30도를 1x 기준으로 사용한다. 같은 센서에서 초점거리만 바꾸는 관계로 `FOV = 2 × atan(tan(30° / 2) / 렌즈 배율)`을 계산한다.
- 0.5x는 약 56.37도, 1x는 30도, 3x는 약 10.21도다. 원본 게임의 실제 수치·보간 방식·렌즈 왜곡을 확인한 결과가 아니다.
- `CameraState.lensMultiplier`에 0.5·1·3을 보관한다. 누락·0·지원하지 않는 값은 1x로 복원한다.
- 초기화용 기본 거리는 1x 화각에서 계산한다. 직전에 선택한 렌즈 때문에 초기화 구도가 바뀌지 않게 한다.

**버튼 전환 처리 제안**
- 카메라 입력을 받는 드래그에서는 양 버튼 조합이 단독 버튼보다 우선한다.
- 단독 드래그 도중 다른 버튼을 추가로 누르면 팬으로, 한 버튼을 놓으면 남은 버튼의 회전으로 전환한다.
- 전환 순간 포인터 기준값을 갱신해 위치·각도가 튀거나 같은 이동량이 두 번 적용되지 않게 한다.
- 단, UI에서 시작한 드래그는 버튼을 추가해도 카메라 제어로 넘어가지 않는다.

## UI와 입력 충돌 방지

**제안**
- 꾸미기 창·드롭다운·팝업·파일 대화상자를 조작할 때 카메라 입력을 차단한다.
- 목록 위 휠은 목록 스크롤에만 사용한다.
- 패널 크기 조절·여닫기는 카메라 출력 영역만 갱신한다. 사용자 회전·팬·거리·화각을 바꾸지 않는다.
- 드래그 시작 대상을 종료까지 유지해 창 밖으로 포인터가 나가도 갑자기 카메라 조작으로 전환되지 않게 한다.
- 앱이 포커스를 잃으면 진행 중인 드래그를 해제한다.

## 패널과 카메라 출력 영역

**확정 (2026-11-03)**
- 패널 닫힘·전체 UI 숨김은 전체 영역, 오른쪽 패널 열림은 왼쪽 영역, 세로 창의 아래 패널 열림은 위쪽 영역을 사용한다.
- 출력 영역 전환은 UI 상태다. 카메라 논리 구도·자동 저장 값·꾸미기 이력을 덮어쓰지 않는다.
- 새 화면비는 반영하되 패널을 열 때마다 FitSize·ResetView로 사용자 구도를 초기화하지 않는다.
- 화각 버튼은 현재 출력 영역의 하단 중앙에서 조금 위, 빠른 안내는 같은 영역의 왼쪽 아래에 둔다.
- 입력 시작 위치가 현재 카메라 영역인지 확인한다. 패널·탭·메뉴·도움말의 입력을 카메라로 넘기지 않는다.
- 그라데이션·3D 배경·벽 가림·툰 표시가 분할된 카메라 영역에서도 정상인지 검증한다.

## 남은 결정

- 팬 이후 회전 시 팬 오프셋 유지·해제·보간.
- 회전·팬·스크롤 감도와 스크롤 방향, 이동·회전·줌 제한.
- 시점 초기화 버튼 제공 여부. 전체 작업 초기화의 카메라 복원은 Reset.md를 따른다.
- 원본 게임과 비교한 렌즈별 실제 화각·전환 감도 조정.
