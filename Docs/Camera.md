## 카메라 조작

## 기준과 근거

2026-11-01 사용자가 직접 설명한 마비노기 모바일의 조작을 기준으로 확정한다. 마우스 좌버튼은 원본 게임의 캐릭터 이동 기능 대신 이 프로그램에서 우버튼과 같은 카메라 회전에 사용한다.

| 입력 | MobiAtelier 동작 | 상태 |
|---|---|---|
| 우버튼만 누르고 드래그 | 캐릭터 기준점을 중심으로 카메라 회전 | 확정 |
| 좌버튼만 누르고 드래그 | 우버튼과 같은 카메라 회전, 캐릭터 이동 없음 | 확정 |
| 좌+우버튼을 누르고 드래그 | 위아래 높이만 이동(게임 스튜디오 카메라, 거리별 범위). 좌우 이동 없음 | 확정(2026-11-15 변경) |
| 마우스 스크롤 | 카메라 거리. 게임 값(한 칸 0.1m, 거리 범위) | 확정(2026-11-15) |
| 회전 감도·반전 | 게임 느낌을 참고해 조정 | 미정 |
| 상하각 제한 | 게임 값(가로 −1°~25°, 세로 4°~25°) | 확정(2026-11-15) |

좌+우 드래그는 기준점 높이만 바꾼다(2026-11-15 사용자 결정, 이전의 right/up 자유 팬을 대체). 드래그로 카메라 전후 이동이나 캐릭터 이동을 하지 않는다. 세부 식은 아래 "게임 스튜디오 카메라"를 따른다.

## 회전 중심과 평행 이동의 관계

**확정**
- 회전 기준은 캐릭터다. 기준점의 몸 기준 높이는 구현 중 조정한다.
- 좌+우 드래그로 구도를 옮겨도 회전 기준점을 이동된 화면 중심이나 임의의 팬 위치로 바꾸지 않는다.
- 이후 좌 또는 우 단독 드래그로 회전하면 다시 캐릭터 기준점 주위의 회전으로 처리한다.
- 회전할 때 캐릭터 모델 자체를 돌리거나 움직이는 방식으로 대체하지 않는다.

**필수 동작 예**
1. 캐릭터를 보고 우버튼 드래그로 회전한다.
2. 좌+우 드래그로 카메라를 옆·위로 옮겨 구도를 바꾼다.
3. 좌 또는 우 단독 드래그로 다시 회전한다.
4. 회전 중심은 여전히 캐릭터다. 2단계의 이동 위치를 새 회전 중심으로 쓰면 안 된다.

**남은 조정**
- 팬은 높이만 바꾸므로 회전 중심은 항상 캐릭터 축 위다(2026-11-15). 회전 감도와 카메라 충돌은 별도 조정한다.
- 상하각·이동 범위·확대·축소는 아래 "게임 스튜디오 카메라"를 따른다.
- 0.5x·1x·3x는 아래 화각 프리셋으로 채택한다(사용자 결정 2026-11-02).

## 화각 프리셋

**확정 (사용자 결정 2026-11-02)**
- 0.5x·1x·3x 버튼을 제공한다. 각각 광각·기본·망원 화각으로 사용한다.
- 휠의 거리 확대·축소와 별도로 렌즈 화각을 바꾼다. 전신·얼굴 프레이밍 버튼으로 대체하지 않는다.
- 렌즈 변경은 카메라 거리·회전·팬·캐릭터 외형을 유지한다. 원하는 크기는 거리 줌과 함께 조절한다.
- 렌즈 선택은 카메라 장면 상태로 자동 저장·JSON 복원 대상이다. 2026-11-03 결정으로 회전·팬·거리·화각은 꾸미기 실행 취소 이력에서 제외한다.
- 카메라 초기화는 기본 렌즈 1x로 돌아간다. 렌즈 값이 없는 이전 저장 파일도 1x로 해석한다.
- 앱 창의 자유로운 화면비 정책은 유지한다. 이미지 저장용 비율 선택·촬영 프레임은 보류한다.

**구현값 (2026-11-15 게임 값으로 교체)**
- 1x 수직 FOV는 게임 스튜디오 카메라 Fov 50°다. `FOV = 2 × atan(tan(50° / 2) / 렌즈 배율)`: 0.5x 약 86.0°, 1x 50°, 3x 약 17.7°. 렌즈 전환은 0.4초에 걸쳐 바뀐다 [확인: 게임 코드]. 배율이 수직 FOV에 걸리는 것은 게임 스크린샷 측정으로 확인했다(0.5x↔1x 크기 비 2.00).
- `CameraState.lensMultiplier`에 0.5·1·3을 보관한다. 누락·0·지원하지 않는 값은 1x로 복원한다.
- 초기화는 1x와 게임 기본 시점(최대 거리·시작 상하각·시작 높이)으로 돌아간다.

**버튼 전환 처리 제안**
- 카메라 입력을 받는 드래그에서는 양 버튼 조합이 단독 버튼보다 우선한다.
- 단독 드래그 도중 다른 버튼을 추가로 누르면 팬으로, 한 버튼을 놓으면 남은 버튼의 회전으로 전환한다.
- 전환 순간 포인터 기준값을 갱신해 위치·각도가 튀거나 같은 이동량이 두 번 적용되지 않게 한다.
- 단, UI에서 시작한 드래그는 버튼을 추가해도 카메라 제어로 넘어가지 않는다.

## 게임 스튜디오 카메라

**확정 (사용자 결정 2026-11-15)**: 게임 스튜디오 촬영 카메라의 값과 식을 따른다. 좌+우 드래그는 위아래만, 거리·상하각 제한은 게임 값, 카메라 영역이 세로로 길면 세로 값을 쓴다.

**데이터 (설치 폴더에서 읽는다, `Sheets/StudioCameraData.cs`)**
- `CameraSettings/CameraPresetSettings.sjon.bin` 의 `StudioModeCameraSetting.Landscape`·`Portrait`: Fov, InitialPitch, MinPitch, MaxPitch, DefaultDistance, MinDistance, 팬 높이 범위 4개, InitialPanningHeight, CameraTargetHeight.
- `StageConstantSettings/StageConstants.sjon.bin`: `PhotoModeCameraSettings.MouseWheelToDistanceRatioOnStudio`(0.1), `RobeAppearanceHeightSettings` 의 성별·연령별 기준 키.
- 파일을 읽지 못하면 2026-11-15 설치본 값으로 대신하고 경고를 남긴다.

| 값 | 가로 | 세로 |
|---|---|---|
| Fov | 50 | 50 |
| 시작 상하각 / 범위 | 3° / −1°~25° | 10° / 4°~25° |
| DefaultDistance / MinDistance | 3 / 1.3 | 4.2 / 1.5 |
| 팬 높이 범위(최소 거리) | 0.2~1 | 0.1~1 |
| 팬 높이 범위(최대 거리) | 0.25~1.1 | 0.25~1.1 |
| InitialPanningHeight / CameraTargetHeight | 0.7 / 0.9 | 0.6 / 0.2 |

**식 [확인: 게임 코드, 2026-11-15]**
- H = 머리 아래 높이(머리 메시 최저점 − 몸 최저점). 기준 키 S = 성별·연령별 상수.
- 최대 거리 = clamp(H / S × DefaultDistance, MinDistance, DefaultDistance). 기본 시점은 최대 거리다.
- t = clamp01((거리 − MinDistance) / (최대 거리 − MinDistance)).
- 팬 높이 범위 = H × lerp(최소 거리 값, 최대 거리 값, t). 시작 팬 높이 = InitialPanningHeight × H.
- 좌+우 드래그: 팬 높이 −= 위쪽 이동 픽셀 / 카메라 영역 높이. 범위 밖으로 나가는 방향만 막는다.
- 기준점 y = 바닥 + 팬 높이 + (CameraTargetHeight − InitialPanningHeight)·H + 0.25·H·(1 − t)(0.2초 보간, 다가가면 얼굴 쪽으로 올라간다).
- 카메라 위치 = 기준점 + 회전·(0, 0, −거리) + 카메라 up·(InitialPanningHeight − CameraTargetHeight)·H.
- 휠: 거리 −= 칸 수 × 0.1 → [MinDistance, 최대 거리]로 자른다. 칸당 120 으로 들어오는 입력은 120 으로 나눈다.

**앱에서 정한 것**
- H 는 게임처럼 외형 변형 바인드 자세가 아니라 현재 포즈의 메시로 잰다. S 는 게임이 외형 변형 경로에서 메시로 다시 계산하는 값 대신 상수를 쓴다 [추정: 근사].
- 휠 한 칸의 게임 원값은 [미확인]이다. 1로 보고 한 칸 0.1m다.
- 거리 추종 시간(0.12초)은 게임 값을 찾지 못해 정했다.
- 가로↔세로 값이 바뀌면 거리 비율 t·팬 높이 비율·상하각을 새 범위로 옮긴다(구도를 초기화하지 않는다).
- 저장 `CameraState.rig` 1 은 이 방식이다. 0(이전 자유 팬 저장)은 방향·렌즈만 쓰고 거리·높이를 기본으로 돌린다.

**검증 (2026-11-15)**: Windows 빌드 2560×1440 촬영. 1x 기본 캐릭터 높이가 화면의 약 73%(게임 75%), 0.5x 머리 꼭대기 y 498(게임 491), 가장 가까운 3x 는 눈~가슴으로 게임과 같은 구도다 [확인: 촬영]. 마우스 드래그·휠 실조작은 [미확인].

## UI와 입력 충돌 방지

**제안**
- 꾸미기 창·드롭다운·팝업·파일 대화상자를 조작할 때 카메라 입력을 차단한다.
- 목록 위 휠은 목록 스크롤에만 사용한다.
- 패널 여닫기는 카메라 출력 영역만 갱신한다. 사용자 회전·팬·거리·화각을 바꾸지 않는다.
- 드래그 시작 대상을 종료까지 유지해 창 밖으로 포인터가 나가도 갑자기 카메라 조작으로 전환되지 않게 한다.
- 앱이 포커스를 잃으면 진행 중인 드래그를 해제한다.

## 패널과 카메라 출력 영역

**확정 (2026-11-03)**
- 패널 닫힘·전체 UI 숨김은 전체 영역, 오른쪽 패널 열림은 왼쪽 영역, 세로 창의 아래 패널 열림은 위쪽 영역을 사용한다.
- 출력 영역 전환은 UI 상태다. 카메라 논리 구도·자동 저장 값·꾸미기 이력을 덮어쓰지 않는다.
- 새 화면비는 반영하되 패널을 열 때마다 FitSize·ResetView로 사용자 구도를 초기화하지 않는다.
- 화각 버튼은 현재 출력 영역의 하단 중앙에서 조금 위, 빠른 안내는 같은 영역의 왼쪽 아래에 둔다.
- 입력 시작 위치가 현재 카메라 영역인지 확인한다. 패널·탭·메뉴·도움말의 입력을 카메라로 넘기지 않는다.
- 그라데이션·3D 배경·벽 가림·툰 표시가 분할된 카메라 영역에서도 정상인지 검증한다.

## 남은 결정

- 회전 감도. 휠 한 칸 원값(게임에서 가장 먼 곳→가장 가까운 곳 칸 수로 확인).
- 시점 초기화 버튼 제공 여부. 전체 작업 초기화의 카메라 복원은 Reset.md를 따른다.
